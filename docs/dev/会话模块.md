# 会话模块

---

## SessionManager (`packages/fp-core/src/fp_core/core/session.py`)

会话管理器负责会话的持久化。它**不持有上下文消息**——只负责读写文件。上下文状态的所有权在 `ConversationState`。

### 类签名

```python
class SessionManager:
    def __init__(self, resume: str | None = None)
```

| 参数 | 类型 | 值 | 行为 |
|------|------|----|------|
| `resume` | `None` / `False` | — | 创建新会话（默认） |
| `resume` | `True` / `"auto"` | — | 续最近会话（按 `updated` 时间） |
| `resume` | `"s_xxx"` | — | 续指定会话 ID（如果存在） |

内部逻辑：先归一化 `resume` 值（`False`→`None`，`True`→`"auto"`），再按分支处理。

### 属性

```python
@property
def session_id(self) -> str
```

当前会话 ID，格式如 `s_260606_160000000000`。

### 会话管理方法

```python
def list_sessions(self) -> dict[str, dict[str, Any]]
```

扫描 `~/.local/share/fp/sessions/` 目录，返回**展示就绪**的会话 meta 字典：
`{sid: {meta_fields}}`（`summary` 保证非空可直接渲染）。三条口径统一在此，
`/resume list`、WebUI 会话面板、ACP session/list 全部复用：

1. **合并当前会话的内存 meta** —— 会话文件是惰性创建的，刚 `/new` 出来的
   会话盘上没文件也必须出现在列表里。旧实现靠「写 meta-only 占位文件」换取
   可见性，正是会话列表被 0 长度记录刷屏的根源，现已改为列表侧合并。
2. **隐藏 0 长度会话** —— 没有消息行且不是当前会话 → 不返回（列表是用来找
   「能续接的对话」的，无一行消息的记录无从续接）。
   判定以 `_scan_messages()` 看**文件实际内容**为准（不信 `message_count`，
   读不出来则视为有内容而保守保留），绝不误伤有效历史。
3. **摘要回填** —— `meta.summary` 缺失时从文件最后一条 user 消息现场推导
   并写回（`updated` 时间戳不动，排序不受影响）；仍算不出时给展示标签
   `EMPTY_SESSION_LABEL`（"(空白会话)"）/ `NO_SUMMARY_LABEL`（"(无摘要)"），
   前端不再退化成显示 sid。

```python
def switch_session(self, sid: str) -> bool
```

切换到指定会话。目标会话必须存在。返回是否成功。
切换成功时会同步进程级「当前会话」标识（见下节），使 `get_current_session_id()` 始终指向活动会话。

```python
def create_session(self, sid: str | None = None, cwd: str | None = None) -> str
```

创建新会话并切换到它。返回新会话 ID。同样同步进程级「当前会话」标识。

`cwd` 是该会话的工作目录（会话根），落进 `meta.cwd`；`None` → 进程当前目录（老行为）。
**前端若允许会话根与进程 cwd 不同（如 ACP 多会话并存），必须显式传**——否则
`session/list` 按 cwd 过滤会把这条会话归到错误的项目下。
`sid` 可预分配：多会话前端需要先把 sid 发给客户端、稍后才真正建档（ACP 的
`session/new` 即如此：先回 `sessionId`，再推 `available_commands_update`）。

```python
def resume_latest(self) -> bool
```

尝试续最近会话（优先 `updated` 最新**且有消息**的会话；目录里只有空占位时才回退到占位文件，避免 `fp -r` / `/resume latest` 落到空会话上）。如果存在历史会话则切换到它并返回 `True`；否则创建新会话并返回 `False`。

```python
def delete_session(self, sid: str) -> bool
```

删除指定会话文件。不能删除当前会话。返回是否成功。

```python
def meta_of(self, sid: str) -> dict[str, Any]
```

读取**任意会话**的 meta（只读，不写盘，不切会话）；会话不存在/`sid` 畸形 → `{}`。

与上面两个「看起来能做同一件事」的 API 分界：

| 想做的事 | 该用 | 为什么不用另一个 |
|---|---|---|
| 读**当前**会话的 meta | `meta`（property） | 它只认当前会话 |
| 列**全部**会话（要展示） | `list_sessions()` | 会扫描并**回填摘要写盘**，读路径带写副作用、代价随会话数线性增长 |
| 读**某条指定**会话的 meta | `meta_of(sid)` | `meta` 读不到别人的；`list_sessions()` 太重且有副作用；`switch_session` 有切换副作用（会打断正在进行的会话） |

典型调用者是前端：ACP 每轮结束时读本轮会话的标题推 `session_info_update`，
而「本轮会话」未必是 core 的当前会话。`sid` 来自协议参数/HTTP path，
故入口处拒绝空串、分隔符与 `.`/`..`（不许拼出会话目录之外的路径）。

```python
def clear_session_file(self)
```

清空当前会话文件（重置为默认 meta，删除所有历史消息）。
**惰性约定**：当前会话文件不在盘上时是 no-op（只重置内存 meta，不落盘）——
「清一个本就空的会话」不该凭空造出 0 长度会话文件（`/new` `/clear` 曾是
占位文件的主要来源之一）。

### 消息读写方法

```python
def save_message(self, role: str, content: str, **kwargs)
```

追加一条消息到文件末尾。自动更新文件内嵌的 meta（`message_count++`, `updated`）。支持 `tool_calls`、`tool_call_id`、`reasoning_content` 等附加字段。

**摘要跟随末条 user**：`save_and_summarize` 先刷 `meta.kw`（检索指纹），再由
`derive_summary` 取**最后一条非系统注入的 user 消息**、截到 `SUMMARY_LIMIT`(20)
字（被截断时末位补 `…`）；带 `source` 的会话（如被拉起的一次性子实例）自动加
`[<source>] ` 前缀（`tagged_summary`，来源标签由派遣方写 `FP_SPAWN_SOURCE`）。摘要**每轮
随末条 user 刷新**——末条是用户最后一次亲口交代的需求，天然有记忆点，
比从 kw 抽词（实测 39.5% 撞车）更可辨认。kw 与 summary 不同源，各司其职：
等于没有摘要。

**人工重命名与 `summary_locked`**：摘要还有**第四条**自动路径需要让路——用户
手工起的名字。`set_summary(sid, summary)` 写 `meta.summary` 的同时置
`meta[SUMMARY_LOCKED]`（`"summary_locked"`），此后所有派生入口一律短路：
`save_and_summarize` 第 3 步前读盘判锁、`_refresh_summary` 首行直接 `return`、
`list_sessions` 的摘要回填跳过（锁定的空名字是用户的表达，不是待修的缺陷）。
没有这一位，用户刚起的名字会被下一条消息改回自动摘要——「改名」就成了
「改到下一句话为止」。`set_summary(sid, "")` = 撤销：清空该位并按末条 user
重算回派生值。锁定只影响摘要，不动 `updated`（改名不改排序位）、不创建文件。

> **思考模型回传约定**：assistant 消息的 `reasoning_content` 会随会话持久化保留。
> 发送给 LLM 时由 `ConversationState.get_messages_for_llm(with_tools=...)` 决定去留——
> 带 `tools` 的请求回传历史思维链（DeepSeek v4 官方要求），不带 `tools` 则剥离省 token。
> 详见《LLM通信》「思考内容跨轮回传」。

> **尾随并入（#238）**：`ConversationState.append_tail_to_last_tool(text)` 把文本并入
> **末条 tool 消息**的 `content` 尾部（末条非 tool 或会话为空则返回 None，调用方走
> 环顶 user 注入）。空闲泵环顶 drain 用它实现忙时系统事件尾随 tool 注入——不新增
> 消息、`msg_count` 不变（故不发 `ON_CTX_APPEND`，避免 bridge 按 `is_append=True`
> 误判断裂）。缓存安全不变式：末条是 tool ⇒ 自该 tool append 后无 assistant 落地 ⇒
> 尚未随任何 LLM 调用发送 ⇒ 并入内容属首次发送，前缀零损失。

```python
def save_context(
    self, context: list[dict[str, Any]], meta_updates: dict[str, Any] | None = None
) -> None
```

将完整上下文**重写**到文件（原子写入：先写 `.tmp` 再 `os.replace`）。跳过第一条 `system` 消息（由 `load_context` 重新加载）。更新 `message_count` 和 `updated` 时间戳。

`meta_updates` 在**同一次写盘**里合进 meta 首行（键级覆盖，非累加）。目前唯一
的携带者是 token 用量：Agent 每轮收尾落盘时带上累计快照，见「token 用量与会话
切换对齐」。用这个参数而不是事后 `update_meta`，是为了一次写盘、也为了让
「正文没变但 meta 该更新」这类情况不至于走两遍整文件重写。

```python
def ensure_on_disk(self) -> bool
```

会话文件是**惰性创建**的：空会话（过滤 `system` 后为空）经 `save_context` 会静默跳过，且 `save_context` 的写失败也被其内部吞掉。`ensure_on_disk()` 在文件不存在时无条件写一行 meta 的占位文件（已存在则 no-op），保证新进程 resume 能通过 `os.path.exists` 校验恢复；返回值 = 文件是否真的在盘上。reload 激活核心（`core/handoff.perform_exec_reload`）落盘后据此做存在性硬校验——文件不在盘上绝不 exec 重启。

```python
def load_context(self, system_prompt: str) -> list[dict[str, Any]]
```

加载会话文件中的所有历史消息。返回的列表第 0 项是传入的 `system_prompt`（作为 `{"role": "system", "content": system_prompt}`），后续项是从文件读取的历史消息（跳过第 1 行的 meta）。

```python
def update_meta(self, sid: str | None = None, *, create: bool = True, **kwargs)
```

更新指定会话的内嵌 meta 字段。自动更新 `updated` 时间戳。如果 `sid` 为 `None` 则更新当前会话。

`create=False` 时文件不在盘上**只改内存 meta、不落盘**：标记类写入
（如派遣产生的 `source` / `parent_sid`）不该给空会话凭空造 0 长度会话文件，标记会随首条
消息一起落盘。（`token_usage` 也走这条惰性约定，但它的写入点已改为下面
`save_context` 的 `meta_updates`，见「token 用量与会话切换对齐」。）

## save_and_summarize 的落盘不变量

```python
def save_and_summarize(
    messages, session_id=None, *, meta_updates: dict[str, Any] | None = None
) -> str
```

所有切换/退出路径的统一「落盘 + 摘要」入口，三条不变量：

| 情形 | 行为 |
|------|------|
| 消息非空 | `save_context` 原子重写文件，摘要 = 末条非注入 user 前 20 字（截断补 `…`） |
| 消息为空 **且** 文件不在盘上 | **完全 no-op**，返回 `""`，不创建文件 |
| 算不出新摘要 | 沿用盘上旧摘要；两者皆空才写 `empty_session` 标记（文件已存在时） |

`meta_updates` 透传给 `save_context`，与正文**同一次写入**——调用方不必
再补一次 `update_meta`（那会整文件重写第二遍）。

第二条是「0 长度会话文件」的根治点：空转的进程退出、`/new` 前的落盘
都不再留下占位文件；第三条保证摘要只增不减，不会被一次空落盘抹掉。

## token 用量与会话切换对齐

`TokenTracker` 是**进程级**的（`State.token_tracker` 与 Agent 共用同一实例），
而 `meta.token_usage` 是**按会话累计**的。两者不自动同步，故有两道约束：

**写入点**：每轮问答收尾 `save_context(_to_save, meta_updates=_token_meta())`。
`_token_meta()` 只在 `call_count > 0` 时返回 `{"token_usage": tracker.to_dict()}`
（累计快照：`total` + `per_model`，含 prompt/completion 与缓存命中细分）。
切换/退出/reload 前的落盘点（`new` / `fork` / `resume` / `handoff`）同样携带——
reload 走 `silent_shutdown` 会跳过 shutdown 结算，那是 exec 前最后一次写盘机会。

**切换对齐**：`SessionManager.bind_token_tracker(tracker)` 在 Agent 构造时绑定，
此后 `create_session` / `switch_session` / `resume_latest` / `clear_session_file`
都会 `_sync_token_tracker()` 把 tracker 对齐到目标会话的 meta 值（无则 `reset()` 归零）。

两条都必要：只写入不对齐，`/new` 会把上一个会话的累计带进新会话（`/resume`
切到历史会话则显示别人的数字）；而「每轮都写」会把这种串味从「退出时体现
一次」放大成「每轮都发生」。

**幂等性**：`reset()` / `restore()` 都是 in-place 改同一对象（替换实例会让共享
它的 `State` 看到旧值）。`update_meta` 是键级覆盖、`accumulate` 只在收到 LLM
usage 响应时调用一次，故同一状态写 1 次或 100 次结果一致。

## 0 长度会话治理：`prune_empty_sessions()`

预防（见上）之外，历史遗留的占位文件用清理收尾：

```python
def prune_empty_sessions(self) -> list[str]        # SessionManager
def session_trash_dir() -> str                     # {SESSIONS_DIR}/.trash/
```

三条全中才动，**移动到 `.trash/` 而非删除**（`.trash` 不匹配会话文件名
模式，不会被 `list_sessions()` 扫到；需要可手工搬回）：

1. 首行是可解析的 meta；
2. 正文**没有任何消息行**（看实际内容，读不出来也视为有内容而跳过）；
3. 不是当前会话。

摘要不作判据——`.trash/` 里连文件带摘要一起保留，判据只认「有没有真实消息」。

命令面入口：`/resume prune`（见《命令参考》）。

## 会话用例层与统一入口（`session_ops` / `ctl.sessions`）

会话管理分三层：**持久化底层** `SessionManager`（只读写文件，见上）、
**用例实现层** `core/session_ops.py`（组合底层完成「新建／切换／清空」等完整用例）、
**统一入口** `fp_core.api.portal.ctl.sessions`（`SessionCtl`，前端唯一调用面）。

`SessionCtl` 收编原 webui／acp／命令层 **8 处手写**「重建 system prompt + reset +
load_context + replace_all」样板，前端只调一次：

| 方法 | 语义 | 返回 |
|------|------|------|
| `new()` | 新建空白会话（落盘当前 → 分配新 sid → 重建上下文），同 `commands/new.py` | `SessionInfo` |
| `load(sid)` | 切换到历史会话 | `SessionInfo`；目标不存在 → `None`（前端决定 404 或自动新建） |
| `clear()` | 清空当前会话文件并重建，同 `commands/clear.py` | — |
| `list()` | 全部会话元数据 `{sid: meta}`，同 `SessionManager.list_sessions()` | `dict[str, SessionMeta]` |
| `delete(sid)` | 删除指定会话文件 | `bool` |
| `update_meta(sid=None, **kw)` | 更新会话 meta（`sid` 缺省 = 当前会话） | — |
| `path(sid)` | 会话文件路径（`session_file_path` 底层，见上） | `str` |
| `read_messages(sid)` | 只读解析会话消息（含 system）；文件不存在 → `None` | `list[dict]` |

`core/session_ops.py` 为上述用例的核心实现，导出 `fork_new` / `switch_to` / `clear` /
`read_messages` 与 `SessionInfo` / `SessionMeta`（后者经 `fp_core.api.types` 再导出，
依赖方向 `api → core`）：

- `fork_new(state)` — 落盘当前 → `create_session` → 重建 → `reset` → `clear_session_file`。
- `switch_to(state, sid)` — 落盘当前 → `switch_session` → 重建并加载目标上下文；
  目标不存在返回 `None`。
- `clear(state)` — 重建 → `reset` → `clear_session_file`。

> `switch_to` 以 `set_messages(prompt, saved)` 整体覆盖，修复原分散实现的两处缺陷：
> acp 用 `replace_all(saved)` 丢 system prompt（`saved` 不含 system 消息）；
> webui／acp 在目标为空会话时残留旧会话消息（空即清空）。

## 会话重建与 prompt 注入重放

`State.rebuild_system_prompt()` 重建 system prompt 后，会**重放**插件注入的
`prompt_appends`（`Agent.ensure_initialized` 在 `ON_INIT` 后捕获并缓存归一化结果），
保证插件 `system_prompt_append` 跨会话重建（`/clear` `/new` `/resume` 及上述
`ctl.sessions` 用例）不丢失。

- 原 webui 独有补丁 `_reapply_prompt_append` 上移归核，acp 侧丢 system prompt 的
  bug 一并修复。
- 初始注入与重建重放共用同一归一化规则：`prompts.normalize_prompt_append`
  （归一化 `str` / `list[str]`、过滤空白段、空行拼接），由 `apply_system_prompt_append`
  实际应用。

### system prompt 随会话固化（默认不重建）

重建会**改写请求序列最前端**，而 LLM 缓存按 token 前缀匹配：差一个字符，后面全部历史
退化为未命中。实测 941 个会话里 41 次 reload，**28 次命中率跌到 ~1%**，累计白付
1,945,423 prompt token（单次最大 162K）——几乎全部来自"重建出的 prompt 与上次不同"。

因此会话**首次定型**即把 prompt 原文写进 meta，此后一律复用：

| 入口 | 行为 |
|------|------|
| `Agent.ensure_initialized` | `initial_prompt = 固化版 or PromptBuilder 构建`；已固化则**跳过** `apply_system_prompt_append`（否则重复注入并改写前缀），随后 `pin_system_prompt()` |
| `rebuild_system_prompt(refresh=False)` | **默认读固化版直接返回**（不碰 `PromptBuilder`、不重放注入段） |
| `rebuild_system_prompt(refresh=True)` | 真重建 + 重放插件段 + `pin_system_prompt(force=True)` 覆盖 |
| `/clear` `/new`(fork) | `refresh=True`（历史已清空，天然付一次全量前缀） |
| `/resume`、`switch_to` | 默认复用——**用的是目标会话自己那份**，不是当前会话的 |

- `clear_session_file()` 只清消息，**保留** `system_prompt` / `system_prompt_at`
  （否则 `/clear` 会悄悄换前缀）。
- 老会话 meta 无该字段 → resume 时按最新构建并补固化（向后兼容）。
- 代价：会话内提示词"过期"（记忆索引、插件段变化要 `/new` 才进 prompt）。有意的取舍
  ——会话上下文里本就比记忆索引有更多信息，而每轮重建的缓存税是纯损失。

## 进程级当前会话（`get_current_session_id`）

```python
def get_current_session_id() -> str | None
```

返回**当前进程内活动会话**的 ID（模块级变量，非 ContextVar）。供插件给事件标注会话归属
（journal 落盘、`parent_sid` 父子关联等）—— 钩子 payload 里并非每条都带 `session_id`。

同步规则：`SessionManager.__init__`、`switch_session()`、`create_session()` 三处注册。
因此 `/resume` 等运行中切换会话后，该值立即指向新会话；切换失败（目标不存在）不改变原值。

> 注意与下一节的区别：这是**进程级单例**（「我现在是哪个会话」），只用于事件归属标注；
> **不要**用它当路径基准——路径基准是下面的 `core/cwd.py`（按 Task 隔离，可多会话并存）。

## 会话级工作目录（`core/cwd.py` + `api/cwd.py`）

```python
from fp_core.api.cwd import current_cwd, resolve_path, set_cwd

current_cwd()        -> str        # 当前 Task 的会话根（未设置→进程 cwd 兜底）
resolve_path(p)      -> str        # 相对路径按会话根拼接，绝对路径原样返回
set_cwd(path)                       # 进入某会话时设置（ContextVar.set）
```

**为什么不用 `os.chdir`**：`chdir` 是**进程级全局可变状态**。用它承载会话 cwd 时，
「相对路径落在本会话项目内」这条 MUST 只能靠「同一时刻只有一个会话在跑」的纪律兜着；
任何在 `await` 之后顺手 `chdir` 的代码（后台 job、subagent、插件、WebUI 多标签）
都会把**正在跑的会话**带到别的项目里——没有异常、没有日志、没有测试会红。

**`ContextVar` 在 asyncio 里按 Task 隔离**：每个 turn 是一个 Task，它内部所有 `await`
出来的代码读到的都是**自己会话的** cwd。于是两个会话并存（哪怕将来放开真并发）也互不污染。
正确性来源从「纪律」升级为「语言机制」。

改造口径（新的代码请照此写）：
- bash/子进程 → `create_subprocess_exec(..., cwd=current_cwd())`，**不要**依赖进程 cwd；
- 文件工具 → `resolve_path(p)` 而不是 `os.path.join(os.getcwd(), p)`；
- 本地记忆 / journal 等落盘目录 → 同样走 `current_cwd()`。

历史依赖点（已全部切换）：`tools/core.py`、`plugins/memory/{read,save,tree}.py`、
`plugins/zeta/plugin.py`、`core/{session,handoff}.py`、`api/portal.py`。

### cwd 是**会话属性**：装载即绑定（`_bind_session_cwd`）

`meta.cwd` 不是记账字段，而是**相对路径基准的所有者**。实现收在
`SessionManager._load_meta_from_session()` 一个点上 —— 所有装载路径
（`__init__` / `create_session` / `resume_latest` / `switch_session`）都经过它，
所以「进入会话 → 相对路径落在该会话项目内」对**每个前端都成立**，
不需要 CLI/WebUI/ACP 各自 `chdir`：

| 时机 | 行为 |
|---|---|
| `switch_session(A)` / `resume_latest()` | 基准 ← `A.meta.cwd`（`/resume`、WebUI 切会话、reload 续接都靠这条）|
| `create_session(cwd=None)` | 基准 ← **当前基准**（继承）；首个会话即进程启动目录 |
| `create_session(cwd=X)` | 基准 ← `X`（ACP `session/new`、subagent 预生成）|
| 老会话无 `meta.cwd` 字段 | **保持当前基准不动**（改造前的会话无从得知，不猜）|
| `meta.cwd` 目录已被删/改名 | **保持当前基准 + 告警**（设进去只会让每个工具都撞 ENOENT）|

**为什么 `create_session` 必须立即落盘 meta（`_ensure_file()`）**：`cwd` 若只活在内存
`_meta` 里，切到别的会话就被覆盖；切回来时文件不存在 → 只能按「当前基准」重新猜一个根
—— 这正是「resume 旧会话落在启动目录」的根因。持久性与可见性已解耦：0 长度会话由
`list_sessions()` 的过滤隐藏（非当前会话不显示），**不需要**再靠「不写文件」压列表。

**`/new` 的语义**：继承当前会话的根。也就是说「启动目录只影响第一个会话」——之后的
会话跟着你当前工作的项目走，`/resume` 回旧会话则跳到它自己的根。这是「会话带自己的
目录」的必然结果，也是终端里 `/new` 手感不变的原因（单会话场景基准恒为启动目录）。

**前端分工**：core 已经在装载时绑好基准，前端**只有一种情况**需要覆盖 —— 客户端在
`session/load` 里声明的 cwd 与落盘 meta 不一致（以客户端为准，仅本轮有效）。
ACP 用 `_session_cwd_apply()` 表达这个例外：基准已等于目标时返回 `None`（不必复位）。

## 会话文件格式

每个会话存储为 **一个 `.jsonl` 文件**，位于 `~/.local/share/fp/sessions/` 目录下。

### 文件结构

```json
// 第 1 行 — meta 信息（JSON 单行）
{"__meta__": true, "id": "s_260606_160000000000", "created": "2026-06-06 16:00:00", "updated": "2026-06-06 16:30:00", "summary": "用户问题概要", "message_count": 12}

// 第 2 行起 — 消息（按时间正序，最新在末尾）
{"role": "user", "content": "Hello"}
{"role": "assistant", "content": "Hi! How can I help?"}
{"role": "user", "content": "查询天气"}
{"role": "assistant", "content": "", "tool_calls": [{"id": "call_xxx", "type": "function", "function": {"name": "get_weather", "arguments": "{\"city\": \"北京\"}"}}]}
{"role": "tool", "content": "{\"temperature\": 25}", "tool_call_id": "call_xxx"}
{"role": "assistant", "content": "北京当前 25°C"}
```

### 格式约定

- **第 1 行** — 固定为 meta 行，包含 `__meta__: true` 标记
- **第 2+ 行** — 消息行，不含 `system`（system prompt 由 PromptBuilder 在加载时重新创建）
- **正序** — 最早的消息在前，最新消息在末尾
- **单文件** — 没有独立的 meta 文件或 `_current` 文件
- **system 不入文件** — 第一条 system 消息在 `save_context` 时被跳过

### meta 字段

| 字段 | 类型 | 说明 |
|------|------|------|
| `__meta__` | bool | 固定为 `true`，用于标识 meta 行 |
| `id` | str | 会话 ID |
| `created` | str | 创建时间 `"YYYY-MM-DD HH:mm:ss"` |
| `updated` | str | 最后更新时间 |
| `summary` | str | 会话摘要：取**最后一条非系统注入的 user 消息**，**硬 20 字上限**（截断补 `…`）。`save_and_summarize` 统一入口生成，**非 LLM**——切换/新建/退出同策略，零 LLM 调用 |
| `message_count` | int | 消息总数（不含 system） |
| `token_usage` | dict | LLM 用量**累计快照**：`total`（prompt/completion/total/call_count + 缓存命中细分）与 `per_model`。每轮随正文落盘，`call_count==0` 不写。老会话可能缺失（旧口径只在退出时结算），缺了就当「未知」不补 0 |
| `system_prompt` | str | **固化**的 system prompt 原文（会话首次定型时写入，resume/reload 一律复用，永不重建——见「system prompt 随会话固化」） |
| `system_prompt_at` | str | 固化时刻 `"YYYY-MM-DD HH:mm:ss"` |
| `cwd` | str | 该会话的**工作目录**（会话根，绝对路径），也是**相对路径基准的所有者**。会话属性而非进程属性：一次连接里可并存多个 cwd 不同的会话，所以不能靠 `os.getcwd()` 现推。装载会话时由 `_bind_session_cwd()` 施加（见「cwd 是会话属性：装载即绑定」）；`create_session` 会**立即落盘**它，老会话缺失时保持当前基准、ACP `session/list` 按 `_meta.cwdUnknown=true` 标记 |

### 加载规则

```python
def load_context(self, system_prompt: str) -> list[dict]:
    context = [{"role": "system", "content": system_prompt}]  # 第 0 项
    # 跳过第 1 行（meta），读取后续所有行
    for line in lines[1:]:
        context.append(json.loads(line))
    return context
```

## 会话 ID 生成

```python
def _generate_sid() -> str:
    base = datetime.now().strftime("s_%y%m%d_%H%M%S%f")  # 微秒级精度
    sid = base
    for i in range(100):
        if not os.path.exists(_session_path(sid)):
            return sid
        sid = f"{base}_{i}"  # 冲突时加自增后缀
    import random
    return f"{base}_{random.randint(1000, 9999)}"
```

**格式**：`s_YYMMDD_HHMMSSffffff`（微秒级，6 位微秒）

**冲突处理**：如果同一微秒内生成重复 ID，依次尝试 `_0`、`_1`……`_99` 后缀。极端情况下加随机后缀。

**文件名**：`s_260606_160000000000.jsonl`

**文件模式匹配**：

```python
SID_PATTERN = re.compile(r"^s_\d{6}_\d{12,}.*\.jsonl$")  # 微秒级 sid
```

## 会话终结：ExitReason

`portal.ctl.close(reason=...)` 以枚举 `ExitReason` 取代原散落的
`silent_shutdown` / `nuclear_exit` 布尔，终结语义收敛为一处：

| reason | 保存上下文 | 摘要 | 删除会话 | 前端提示 |
|--------|-----------|------|---------|---------|
| `FINAL` | ✅ | ✅ | ❌ | 显示退出提示 |
| `RECYCLE` | ✅ | ✅ | ❌ | 静默（reload / webui 重建） |
| `DISCARD` | ❌ | ❌ | ✅ | 静默（原 `nuclear_exit` / acp 退出） |

会话文件（`~/.local/share/fp/sessions/<sid>.jsonl`）的产出与销毁由此统一：
`FINAL` / `RECYCLE` 落盘并写摘要，`DISCARD` 删除当前会话文件后静默。

## 热重启续接：ReloadDirective

热重启（reload）后的续接消费收编为 `portal.ctl.take_reload()`，返回结构化结果：

```python
@dataclass(frozen=True)
class ReloadDirective:
    notice: str | None          # kind=command 的完成提示行（前端自行渲染），None = 无
    should_continue: bool       # kind=tool 的有效续接，True 时前端驱动续接
```

它取代原前端手写的 `consume_reload_handoff` + `_reload_notice` + `_pending_continue`
样板（置位与清空均在内部完成），前端只读结构化结果：

```python
d = portal.ctl.take_reload()
if d.notice:
    前端渲染(d.notice)
if d.should_continue:
    resp = await portal.run.continue_(io=...)
```

## 会话关键词（`meta.kw`）

summary 与 kw **不同源**（前者是末条 user 原话，后者是检索指纹）：**存 12 个
（`TOP_STORE`）、列表渲染前 5 个（`TOP_SHOW`）**，检索吃全部 12 个。
它是有**区分性**的关键词快照，由
`core/session_keywords.py` 的 KL 管在**会话落盘时**算好（纯本地统计，零 API）。

| 字段 | 含义 |
| --- | --- |
| `kw` | 关键词列表（3 个）。旧会话可能缺失 → 列表**留空**，绝不在渲染时补算 |
| `kw_v` | 索引版本（管线语义变化时 +1，用于判定过期） |
| `fork_from` | `{sid, msg_count}`，`/fork` 时写入；关键词只统计分叉之后的增量 |

**为什么绝不惰性计算**：`list_sessions()` 是 900+ 会话的循环，单会话 18ms 的实算
会把毫秒级列表拖成秒级。渲染路径只读现成字段，缺失即留空。

**背景模型 P_C**：按天分桶存于 `{SESSIONS_DIR}/.kw/df-YYYYMMDD.json`，取最近 21 天
合并（毫秒级）。日常新会话**不写桶**，只有低频 `rebuild_all()`（≈55s/900 会话）才
刷新桶与全部 `kw`——背景是「日常语料」，滞后几天的影响远小于每次落盘重写桶的代价。

**fork 与关键词扎堆**：`/fork` 是物理复制消息，父子共享前缀。实测同组关键词
Jaccard 0.372 vs 非 fork 配对 0.080，故 `fork_from` 记录分叉点，打分只取其后内容。

手动维护：`python -m fp_core.core.session_keywords rebuild | show`。
jieba 为可选依赖（`fp-core[kw]`），缺失时退化为 bigram 切分，功能不中断。
