# 配置指南

FP 通过 `~/.config/fp/config.json` 文件进行配置，同时支持环境变量覆盖。所有配置项在启动时按优先级加载（配置文件显式值 > 环境变量）。

## 首次配置（交互式向导）

FP **没有任何内置的连接默认值**：`LLM_API_KEY` / `LLM_API_BASE_URL` / `LLM_MODEL` 三项必填，
缺一即无法启动。首次在交互终端运行 `fp` 时，若检测到配置缺失，会自动进入配置向导：
依次询问三项（密钥隐藏回显），完成后写入配置文件并**立即生效**（无需重启）。

- 非交互环境不会阻塞，而是打印含配置文件绝对路径的指引并以非 0 退出——涵盖管道、`--headless`、`-m`、无 tty 的 `webui`、`acp`、子进程；
- `cli` 与 `webui` 在交互终端下都会进入向导（`webui` 不读 stdin，浏览器走独立通道）；`acp` 一律不进（其 stdin 是 IDE 的 JSON-RPC 协议流，占用即破坏协议）；
- 三键也可直接经环境变量提供（见下）。

运行期用户数据（会话、记忆、日志）位于数据目录 `~/.local/share/fp/`——代码中请通过 `config.data_dir()` 获取：它在运行期读取当前数据目录（测试 monkeypatch `_FP_DATA_DIR` 后保持一致），**不要在导入期缓存其派生路径**。

## config.json 完整字段

```json
{
  "LLM_API_KEY": "sk-your-api-key-here",
  "LLM_API_BASE_URL": "https://api.deepseek.com/v1",
  "LLM_MODEL": "deepseek-v4-flash",
  "TEMPERATURE": 0.8,
  "MAX_TOKENS": 32768,
  "TIMEOUT": 300,
  "RETRY_COUNT": 3,
  "MAX_ITERATIONS": 50,
  "MAX_CONTEXT_TOKENS": 8000,
  "tui": {
    "styles": {
      "info": "green",
      "error": "bold bright_red",
      "warning": "yellow",
      "yellow_bold": "bold yellow",
      "hint": "magenta",
      "llm_thought": "dim magenta",
      "llm_tool": "yellow",
      "startup": "green",
      "logo": "magenta"
    }
  },
  "display_truncation": {
    "llm_thought": 100,
    "llm_tool": 300,
    "logo": -1
  }
}
```

## 字段详解

### LLM 连接配置

| 字段 | 必填 | 类型 | 默认值 | 说明 |
|------|------|------|--------|------|
| `LLM_API_KEY` | 是 | string | 无（必填） | LLM 服务的 API 密钥，兼容任何 OpenAI 接口协议的提供商 |
| `LLM_API_BASE_URL` | 是 | string | 无（必填） | API 基础地址，如 `https://api.deepseek.com/v1` |
| `LLM_MODEL` | 是 | string | 无（必填） | 模型名称，需与 API 提供商支持的模型名一致 |
| `TEMPERATURE` | 否 | float | `0.8` | 生成温度，值越高输出越随机。范围 0.0 ~ 2.0 |
| `MAX_TOKENS` | 否 | int | `32768` | 单次 LLM 调用的最大输出 Token 数 |
| `TIMEOUT` | 否 | int | `300` | HTTP 请求超时时间（秒） |
| `RETRY_COUNT` | 否 | int | `3` | LLM 调用失败时的重试次数 |

### 多供应商 / 模型（LLM_PROVIDERS 两级结构，可选）

只用单个供应商时，顶层三键（`LLM_API_KEY` / `LLM_API_BASE_URL` / `LLM_MODEL`）就够。
需要**一个供应商挂多个模型**或**不同供应商有同名模型**时，用两级命名空间：

```jsonc
{
  // 当前激活项 = 唯一引用（供应商/模型），取代顶层三键副本
  "ACTIVE_LLM": "deepseek/deepseek-v4-flash",

  "LLM_PROVIDERS": {
    "deepseek": {
      "api_key": "sk-…",
      "base_url": "https://api.deepseek.com/v1",
      "timeout": 300,               // 可选：连接参数（provider 级）
      "models": {
        "deepseek-v4-flash": {},    // 模型级只写差异
        "deepseek-reasoner": { "temperature": 0.0, "max_tokens": 8192 }
      }
    },
    "aliyun": {
      "api_key": "sk-…",
      "base_url": "https://…/compatible-mode/v1",
      "models": { "qwen-max": { "extra_body": { "enable_thinking": true } } }
    }
  }
}
```

规则：

- **provider** = 一个 API 端点（`api_key` + `base_url`）；`models` 下可挂任意多个模型，端点凭证只写一份（DRY）。
- 模型名只需在 **provider 内**唯一；不同供应商的同名模型是不同叶子，用 `provider/model` 全名区分。
- 参数覆盖链：**模型级 → provider 级 → 顶层全局（`TEMPERATURE`/`MAX_TOKENS`/…）→ 内置默认**。可覆盖项：`temperature`、`max_tokens`、`extra_body`（`extra_body` 为浅合并：provider 打底、模型覆盖）。
- **思考模式控制**：统一用意图键 `enable_thinking`（布尔）写在 `extra_body`，解析时按目标 provider 翻译为原生请求参数——qwen/DashScope 等保持 `{"enable_thinking": true/false}`；DeepSeek 翻译为 `{"thinking": {"type": "enabled"/"disabled"}}`。DeepSeek 的思考档位 `reasoning_effort`（`low/high/max`）直接写在 `extra_body` 中（会被平铺到请求体顶层，符合其 API 要求）。跳过翻译也可直写原生 `thinking` 格式。未配置时默认关闭思考。注意：思考模式下 `temperature` 等采样参数会被服务端忽略。
- **激活**：`ACTIVE_LLM` 键 = `"provider/model"`。缺失时自动由顶层三键推导一次（兼容旧配置）；旧扁平格式（provider 直接带 `model` 字段）会在首次使用 `/model` 时自动迁移为两级结构并写回。
- 运行时切换用 `/model` 命令（列出树 / `provider/model` 精确切 / 供应商名单模型切 / 模型名全局唯一切；同名需消歧）。切换持久化到 `ACTIVE_LLM`，重启后保持。> 💡 `/model` 是 **fp-ext 分发的用户级扩展命令**（非仓库内置），随部署环境出现；未安装时可手动编辑 `ACTIVE_LLM` 键或用 `fp ext` 获取。
- 顶层三键在配置了 `LLM_PROVIDERS` 时仍是激活项的**兼容镜像**（旧读者可继续读）；`TEMPERATURE`/`MAX_TOKENS` 保持「全局默认」语义，不会被切换写脏。

### Agent 行为配置

| 字段 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `MAX_ITERATIONS` | int | `50` | 单次用户消息的最大工具调用迭代次数，超过则强制跳出防止无限循环 |
| `MAX_CONTEXT_TOKENS` | int | `8000` | 上下文窗口阈值（Token 数），超过时启动压缩策略 |

### 进程级模型覆盖：`fp --model` / `FP_MODEL`

`fp --model <spec>` 通过环境变量 `FP_MODEL` 在 **config 模块加载时**生效（入口在 import `fp_core` 前预扫描 argv 落地），优先级**高于** `ACTIVE_LLM`，仅作用于本进程、不写盘：

- `spec` 为 `provider/model` → 精确指定；
- `spec` 为裸模型名 → 消歧次序：① 当前激活 provider 命中；② 全表唯一命中；
- **查无 / 跨 provider 歧义 → 不猜**：回退到配置的 `ACTIVE_LLM` 激活项，并在 `check_llm_config()` 告警提示改用 `provider/model` 精确指定；
- 旧扁平配置（无 `LLM_PROVIDERS` 表）→ 直接覆盖 `LLM_MODEL`（`provider/` 前缀忽略）。

也可手动 `export FP_MODEL=…` 获得同样效果（子进程继承，subagent 与父进程同模型）。

## 显示配置

### 样式配置：`tui.styles`（终端前端共用）

> 旧的顶层 `display_styles` 段（`{"color": "...", "bold": true}` dict 条目格式）**已废弃，无兼容层，代码不再读取**。样式统一在 `tui.styles` 下配置——`tui` 段管的是**终端前端**（REPL 与 TUI 共读一张样式表），避免与 webui 等其他前端混淆。

每个样式名 → 一个 **rich 样式字符串**（如 `"bold bright_red"`）。REPL 的 ANSI 着色通道只认以下颜色名与效果词，其余 token（`#hex`、256 色名、`underline`…）静默忽略；TUI 走 rich 通道，支持 `#hex` 与全部 rich 色名。

- 可用颜色名（ANSI 通道）：`black`、`red`、`green`、`yellow`、`blue`、`magenta`、`cyan`、`white`、`bright_red`、`bright_green`、`bright_yellow`、`bright_cyan`、`bright_white`、`default`
- 效果词：`bold`（粗体）、`dim`（暗淡）、`italic`（斜体）

**REPL 侧样式名**（未配置 = 无色）：

| 样式名 | 参考配置 | 用途 |
|--------|---------|------|
| `info` | `"green"` | 一般信息提示、操作成功反馈 |
| `error` | `"bold bright_red"` | 错误消息 |
| `warning` | `"yellow"` | 警告信息 |
| `yellow_bold` | `"bold yellow"` | 强调性警告，如中断标记 |
| `hint` | `"magenta"` | 行为引导提示 |
| `llm_thought` | `"dim magenta"` | LLM 思考过程的灰色显示 |
| `llm_tool` | `"yellow"` | 工具调用和结果的显示 |
| `startup` | `"green"` | 启动横幅 |
| `logo` | `"magenta"` | ASCII Logo 艺术字 |

上表只是常用示例；TUI 侧的语义键（`prompt`/`status_busy`/`think`…）见下方 `tui` 章节，两组键都在同一个 `tui.styles` 里配置，全集见 `fp_cli/appearance/schema.py` 的 `DEFAULT_STYLES`。

### display_truncation

控制 LLM 流输出在终端中的截断策略。值为 `-1` 表示不截断。

| 截断名 | 默认值 | 说明 |
|--------|--------|------|
| `llm_thought` | `100` | LLM 思考过程的截断长度（字符数），超出部分以 `… <+N chars>` 省略 |
| `llm_tool` | `300` | 工具调用及结果的截断长度（字符数） |
| `logo` | `-1` | 启动 Logo 不截断（始终完整显示） |

### tui

TUI（Textual 界面）与 REPL 的外观：主题、调色板、语义样式、符号、ASCII 开关。
**缺省 = 现有外观**，任何坏数据（坏 JSON、未知主题名、非法色值）静默回落默认，不会阻断启动。

> **不需要记键名，也不需要手改这里**：TUI 里按 **`Ctrl+T`** 打开**外观设置面板**——
> 五个分页（主题 / 配色 / 样式 / 符号 / 通用）把所有可配置项都列成「中文标签 + 当前值」，
> 上下选、回车改、`r` 恢复默认，主题还能上下即时预览。改完自动写回本段——**config 只做记录**。
> 下面的字段是给「想锁死一套外观」或「写进 dotfiles 分发」的人用的。

```jsonc
"tui": {
  "theme": "dracula",        // 21 个内置主题名之一；留空 ""（默认）或 "custom" = 跟随 Textual 默认，此时 palette 可用
  "palette": {               // 自定义调色板（theme="custom" / 留空 时生效）；全部 14 项，面板「配色」分页同名可改
    "primary": "#0178D4",    // 主色（按钮等）
    "secondary": "#004578",  // 次色
    "accent": "#ffa62b",     // 强调色（选中、按钮 hover、弹窗边框）
    "foreground": "#e0e0e0", // 前景 / 正文文字
    "success": "#4EBF71",    // 成功
    "warning": "#ffa62b",    // 警告
    "error": "#ba3c5b",      // 错误
    "dark": true,            // 深色 / 浅色模式
    "luminosity_spread": 0.15,  // 明度跨度（0~1，主题派生色阶用）
    "text_alpha": 0.95       // 文字透明度（0~1）
    // background / surface / panel / boost 默认不设 = 继承 textual-dark 底板；
    // 要改就写 "surface": "#181825" 这样一项（面板里改色也是写这些键）
  },
  "styles": {                // 语义样式：REPL 与 TUI 共读一张表（rich 样式串）
    "info": "cyan",          // 未列出的键回落内置默认（见 fp_cli/appearance/schema.py 的 DEFAULT_STYLES）
    "prompt": "bold cyan",   // 用户输入行（❯ ...）
    "status_busy": "bold"    // 状态条运行中
  },
  "symbols": {               // 符号字形：REPL 与 TUI 共用同一张表
    "bot": "🤖",             // 欢迎头 / 启动横幅
    "prompt": "❯",           // 输入行前缀（REPL 提示符 + 用户消息行）
    "busy": "🔴"             // 状态条运行中
  },
  "ascii": false             // true = 符号整体换 ASCII 降级（缺字形字体救急）
}
```

- **内置主题**（21 个，`theme` 直接填名字）：`textual-dark`、`textual-light`、`dracula`、`nord`、`gruvbox`、`catppuccin-mocha`、`catppuccin-latte`、`catppuccin-frappe`、`catppuccin-macchiato`、`tokyo-night`、`monokai`、`solarized-light`、`solarized-dark`、`rose-pine`、`rose-pine-moon`、`rose-pine-dawn`、`atom-one-dark`、`atom-one-light`、`flexoki`、`ansi-dark`、`ansi-light`
- **优先级**：`theme` 填了合法内置名 → 用它（`palette` 被忽略）；`theme` 留空或填非法名 → 走 `palette`；两者都没有 → 保持默认
- **两者互斥**（一个主题就是一套配色的集合包）：在面板里**改配色会自动清掉 `theme`**，切到自定义配色；反之在面板里选定内置主题后，`palette` 仍在 config 里但不再生效
- `init_config()` 生成的 config.json **默认就带 `tui` 段**（`theme` 为空串，其余空 dict）：结构一目了然，想锁死外观时直接填字段即可
- **本段由 TUI 现场写入**：面板里选定主题 → 写回 `theme`；改色 → 写回 `palette.<键>`；改样式/符号/开关 → 写回 `styles`/`symbols`/`ascii`。只有**内置**主题名会落盘（`fp-custom` 例外——它是 `palette` 的派生结果，写进去会变成下次启动不认识的鬼名字）
- 面板里 `r` = 删掉该项配置（回落出厂默认）；`palette` 的项删空后，自定义主题自动退回 Textual 默认
- `palette` 未列出的字段自动继承 `textual-dark` 底板；单个非法色值只丢该键，其余照用
- 色值支持 `#hex`（`#RGB` / `#RRGGBB`）与 rich 色名（`cyan`、`bright_red`…）

**styles（语义样式）**：键 → rich 样式串（如 `"bold cyan"`）。全部键与默认值见 `fp_cli/appearance/schema.py` 的 `DEFAULT_STYLES`（面板「样式」分页里同名可改，改完行内即时预览），常用的有：

| 键 | 默认 | 作用 |
|----|------|------|
| `info` / `warning` / `error` | `cyan` / `yellow` / `red` | 日志三级（REPL 同名键共用此表，一处配置两端生效） |
| `prompt` | `bold cyan` | 用户输入行 |
| `think` / `tool` / `tool_result` | `dim` / `magenta` / `dim` | 思考流 / 工具调用 / 工具结果 |
| `status_busy` / `status_idle` | `bold` / `green` | 状态条两态 |
| `hint` / `keys` / `completion` | `cyan` / `dim` / `bold cyan` | 帮助行 / 键位行 / 斜杠补全 |

**symbols（符号）**：键 → 单个字形。全部键见 `DEFAULT_SYMBOLS`（19 键）：

| 键 | 默认 | 位置 |
|----|------|------|
| `bot` `hint` `keys` `ask` `stats` `think` | 🤖 💡 ⌨ ❓ 📊 💭 | 欢迎头 / 引导行 / 键位行 / 提问 / 统计 / 思考流标签 |
| `prompt` `queued` `send` | ❯ ⏳ ↑ | 输入行前缀 / 已排队标记 / 发送按钮 |
| `busy` `idle` `reject` `reload` `stop` `paused` | 🔴 🟢 ⛔ 🔄 ⏹ ⏸ | 状态条两态 / 忙碌拦截 / reload / 中断 / 经典 REPL 降级提示 |
| `tool` `tool_result` | ⚙ 📋 | 工具调用行 / 工具结果行 |
| `session_end` `headless` | 📂 🖥 | 退出面板标题 / 无头驻留横幅 |

- **REPL 与 TUI 共读这张表**：REPL 侧（`display.py` / `main.py` / `cli_io.py`）与
  TUI 侧（`tui.py`）的 emoji 全部来自 `tui_glyph()`，改一处两端同时变
- **`ascii: true`**：符号底表整体换成 ASCII（`❯`→`>`、`🔴`→`[!]`…），终端字体缺字形（豆腐块）时的一行救急；REPL 与 TUI 同时生效，`symbols` 里的显式配置仍优先于 ascii 底表
- 生效时机：下次启动 REPL 或 TUI，改完无需动其他文件
