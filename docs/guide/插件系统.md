# 插件系统

## 架构

插件系统采用**生命周期钩子驱动**的架构。系统在运行的关键节点触发钩子，已注册的插件按优先级依次执行对应的钩子函数。

**工作流程**

```
[系统事件] ──触发──→ [钩子调度器] ──依次调用──→ [已注册的插件钩子函数]
```

---

## 生命周期钩子

系统共定义了 **50 个生命周期钩子**，按阶段分组。所有钩子均为**执行钩子**：可修改传入数据、守卫（阻止/取消）流程；载荷不可变的钩子点（`ON_INIT`/`ON_SHUTDOWN`/`ON_CLEANUP`）即插件执行注册/清理动作的时机。下表为核心钩子速览，**完整 50 个清单（含边编号与 payload 字段）见 [插件系统（开发）§6.2](../dev/插件系统.md)**。

| 阶段 | 钩子 | 类型 | 触发时机 |
|------|------|------|----------|
| **初始化** | `ON_INIT` | 执行 | Agent 初始化完成 |
| | `ON_INITIALIZED` | 执行 | 初始化检查通过（首次或幂等跳过） |
| | `ON_CONFIG_LOADED` | 执行 | 配置加载完成 |
| **消息处理** | `ON_MESSAGE_FILTER` | **执行** | 用户消息过滤/修改 |
| | `ON_MESSAGE_RECEIVED` | 执行 | 消息已接收 — 提交前可修改/拦截 |
| | `ON_MESSAGE_BLOCKED` | 执行 | 消息被插件拦截（早退不落盘） |
| **命令** | `ON_BEFORE_COMMAND` | 执行 | 命令开始执行 — blocked 可阻断 |
| | `ON_COMMAND` | 执行 | 命令输出返回 — 唯一命令 post 点 |
| | `ON_COMMAND_BLOCKED` | 执行 | 命令被守卫阻断 — 守卫分支 post 出口 |
| **LLM 调用** | `ON_BEFORE_LLM_CALL` | **执行** | LLM 调用前 — 可修改 messages/tools 或取消 |
| | `ON_AFTER_LLM_CALL` | **执行** | LLM 返回后 — 可修改 response 或阻止工具 |
| | `ON_CTX_APPEND` | 执行 | 消息入库后 — append 后唯一 post 观察点 |
| | `ON_SESSION_SAVE` | 执行 | save_context 覆写磁盘 — 状态存档点 |
| **响应** | `ON_BEFORE_RESPONSE` | **执行** | 返回响应前 — 可修改 content |
| **工具** | `ON_TOOL_SELECT` | **执行** | 工具已选择 — 可修改列表/阻止执行 |
| | `ON_TOOL_CALL` | **执行** | 工具即将调用 — 可修改参数/暂停/拒绝 |
| | `ON_TOOL_RESULT` | **执行** | 工具调用完成 — 可审查/修改/过滤结果 |
| | `ON_TOOL_ERROR` | **执行** | 工具出错 — 可处理/覆盖错误 |
| **上下文** | `ON_CONTEXT_UPDATE` | 执行 | 上下文已更新 — 保存前可修改本轮消息 |
| **错误** | `ON_ERROR` | 执行 | 发生错误 — 可覆盖错误信息，handled 恢复主循环 |
| **资源** | `ON_SHUTDOWN` | 执行 | 关闭中 |
| | `ON_CLEANUP` | 执行 | 清理资源 |

## 内置插件

### 通知插件

在交互式模式下，通知插件在以下时机触发桌面通知和提示音：

- `ON_AFTER_LLM_CALL`：Agent 回复完成后，发出通知提醒用户查看
- `ON_ERROR`：发生错误时，发出告警通知

通知通过 `kdeconnect_notify` 工具（用户级）可同步推送到手机。

### 任务系统插件

通过 `ON_INIT` 注册 6 个任务工具（`task_create` / `task_read` / `task_update` / `task_edit` / `task_list` / `task_clear`，操作**任务图** taskmap）；`ON_BEFORE_LLM_CALL` 自动附加任务进度提醒。

### shortcircuit 插件

通过 `ON_INIT` 做两件事：
1. 注册 `shortcircuit` 工具（工具层硬性策略：当前块强制退化、其他块默认 crop）
2. 通过 `register_command("sc", command)` **注入 `/sc` 命令**（不走 commands/ 自动发现；插件被禁用时 `/sc` 一并消失）

## 插件开发概览

### 开发步骤

1. 继承 `Plugin` 基类
2. 实现 `on_register` 方法
3. 在 `on_register` 中用 `lifecycle.register(LifecycleHook.ON_XXX, handler)` 注册钩子
4. 将插件文件放入插件目录（内置 `fp_core/plugins/` 或用户三来源目录，默认 `~/.local/share/fp/private/plugins/`）

### 最小示例

```python
from fp_core.core.lifecycle import LifecycleHook
from fp_core.plugins.base import Plugin

class HelloWorldPlugin(Plugin):
    """一个简单的示例插件"""

    def on_register(self, lifecycle):
        """注册钩子"""
        lifecycle.register(LifecycleHook.ON_INIT, self.on_start, name="hw_start")
        lifecycle.register(LifecycleHook.ON_MESSAGE_RECEIVED, self.on_user_message, name="hw_msg")

    async def on_start(self, ctx, **kwargs):
        """系统启动时执行"""
        print("👋 HelloWorld 插件已加载")

    async def on_user_message(self, ctx, **kwargs):
        """收到用户消息时执行"""
        content = ctx.data.get("content", "")
        if "hello" in content.lower():
            print("🌍 用户说了 hello！")
```

### 钩子函数签名

所有钩子函数均为异步函数，接收与触发时机相关的上下文参数。具体参数请参考基类中的类型注解。
