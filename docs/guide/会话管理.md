# 会话管理

## 自动保存

每次用户交互完成后，系统自动将会话保存到 `~/.local/share/fp/sessions/` 目录。该目录是**全局目录**（不区分 workspace）：无论从哪个工作目录启动，读写的都是同一份会话。

**文件命名格式**

```
s_YYMMDD_HHMMSSffffff.jsonl
```

例如：`s_260610_153022123456.jsonl`

**文件结构**

- 第 1 行是 meta 行（JSON 格式），包含字段：
  - `id`：会话唯一标识
  - `created`：创建时间戳
  - `updated`：最后更新时间戳
  - `summary`：会话摘要（自动生成）
  - `message_count`：消息总条数
  - `source`：来源标记（可选，`"subagent"` 表示子代理任务会话）
- 第 2 行起，每行一条消息记录，按正序存储，格式为 JSON

示例：

```jsonl
{"id": "s_260610_153022123456", "created": "2026-06-10T15:30:22", "updated": "2026-06-10T16:45:10", "summary": "讨论了配置文件修改和技能热重载", "message_count": 12}
{"role": "user", "content": "你好，请帮我修改配置", "timestamp": "2026-06-10T15:30:22"}
{"role": "assistant", "content": "好的，请告诉我需要修改什么配置", "timestamp": "2026-06-10T15:30:25"}
```

assistant 消息还可带 `tool_calls`、`reasoning_content`（思考模型的思维链）等附加字段。
其中 `reasoning_content` 的后续回传策略：带工具调用的请求会回传历史思维链（思考模型
多轮推理所必需），纯文本请求则自动剥离（服务端会忽略，避免浪费 token）。

## 会话列表

使用 `/resume` 命令（不带参数）列出所有历史会话，按更新时间倒序。

**交互示例**

```
> /resume
## 📂 会话列表
使用 `/resume <sid>` 切换，`/resume latest` 切换到最新
`[subagent]` = 子代理任务会话，`/resume --main` 只看主会话

- **[1]** 🔹 [subagent] 分析 ELF 文件 (5条, `s_260710_120000123456`)
- **[2]** 讨论了配置文件修改和技能热重载 (12条, `s_260610_153022123456`) ⬅
- **[3]** 编写单元测试用例 (8条, `s_260609_090011654321`)
```

- 当前会话以 `⬅` 标记
- 🔹 / `[subagent]` 前缀 = 子代理任务会话（由 subagent 工具自动创建）
- 使用 `/resume --main` 只列出主会话（过滤 subagent 子任务会话）

## 恢复会话

支持三种恢复方式：

### 命令行启动时恢复

```bash
# 恢复最近的会话
python3 cli.py -r

# 恢复指定会话
python3 cli.py -r s_260610_153022123456
```

### 运行中恢复

在交互界面中使用 `/resume` 命令：

```
# 恢复最近的会话
> /resume latest

# 恢复指定会话（支持 sid 或列表序号）
> /resume s_260610_153022123456
> /resume 2

# 只看主会话（过滤 subagent 子任务会话）
> /resume --main
```

恢复后会将会话历史载入上下文，可继续之前的对话。

切换动作本身立即落盘：当前（旧）会话先保存并生成摘要（**非 LLM**：取最后一条用户消息前
20 字符，`save_and_summarize` 统一入口，切换零等待），随后把切换后的上下文写入
目标会话、刷新其 `updated` —— 因此切换后即使进程立刻退出，重启续接的也是**目标会话**
（启动时按 `updated` 取最新会话，不刷新会退回旧会话）。运行中切换还会同步进程级
「当前会话」标识，插件侧事件归属随之指向新会话。

新建（`/new`）、切换（`/resume`）与清空（`/clear`）都会重建系统提示词，并重放插件
注入的提示词片段——插件追加的指令跨会话不丢失。

### 热重启后自动恢复

`/reload`（进程级热重启）执行时先将当前会话落盘，新进程以 `FP_RELOAD_SID`
自动恢复同一会话；入口显示一行 `🔄 热重启完成，会话 xxx 已恢复` 后即回到
正常输入（不进续接），对话上下文无缝延续。旧的原地重建式热重载已废弃删除；
`/reload modules` 仅原地重载模块代码，不切换会话。

热重启的提示与续接由新实例统一处理：若重启由模型在对话中自行触发（工具面，例如改完
自身代码后自举），新实例会先显示恢复提示，再自动续接被中断的那一轮；若是用户手动
`/reload`（命令面），则只恢复会话、回到正常输入，不进续接。

## 退出与会话留存

退出方式决定当前会话是否留存，分三种：

| 退出方式 | 保存上下文 | 生成摘要 | 删除会话文件 | 提示 |
| --- | --- | --- | --- | --- |
| `FINAL` 正常退出 | ✅ | ✅ | ❌ | 显示退出提示 |
| `RECYCLE` 热切换 | ✅ | ✅ | ❌ | 静默 |
| `DISCARD` 不留痕退出 | ❌ | ❌ | ✅ | 静默 |

- **正常退出**（`FINAL`）：终端正常结束（如 `Ctrl-D` / 输入 EOF）时，保存上下文、生成摘要并显示退出面板。
- **热切换**（`RECYCLE`）：`/reload` 重启、WebUI 重建实例时，旧实例保存上下文并生成摘要，静默收尾。
- **不留痕退出**（`DISCARD`）：ACP 会话结束等场景下，直接删除当前会话文件，不保存、不生成摘要。

无论哪种方式，会话文件都位于全局目录 `~/.local/share/fp/sessions/`；只有 `DISCARD` 会把当前会话从列表中移除。

## 分支 Fork

`/fork` 命令基于当前上下文创建一个新的会话分支。

**行为说明**

- 新会话继承当前上下文中的所有消息
- 原会话保持不变，系统自动为其生成摘要标签
- 新会话获得新的会话 ID，从 fork 点继续对话

**示例**

```
> /fork
🔄 会话已分叉！
   原会话: s_260610_153022123456（已保存归档）
   新会话: s_260610_170000789012（继续对话）
```

## 会话文件管理

### 文件位置

所有会话文件存储在 `~/.local/share/fp/sessions/` 目录下。

### 备份

直接复制整个目录即可备份：

```bash
cp -r data/sessions/ backup/sessions_20260610/
```

### 查看

```bash
# 列出所有会话文件
ls -lh data/sessions/

# 查看会话元信息
head -1 data/sessions/s_260610_153022123456.jsonl | python3 -m json.tool

# 查看会话摘要
head -1 data/sessions/s_260610_153022123456.jsonl | python3 -c "import sys,json; print(json.load(sys.stdin)['summary'])"
```

### 清理空会话

目前**没有内置的清理命令/工具**；删除会话请使用：

```
/resume list              # 查看会话列表
/resume delete <sid|序号>  # 删除指定会话（当前会话不可删）
```

如需批量清理仅含 meta 行、无实际消息的会话文件，可手动删除 `{DATA}/sessions/` 下对应 `.jsonl` 文件（删除前建议先备份）。
