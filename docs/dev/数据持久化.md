# 数据持久化

系统维护三类持久化数据：会话记录、长期记忆、任务列表，分别存储在 XDG 兼容路径下。

---

## 会话文件格式

会话文件位于 `~/.local/share/fp/sessions/`，命名格式 `s_{uuid}.jsonl`。

### JSONL 格式细节

每行一个独立的 JSON 对象，**行内不允许有换符**。

### 关键规则

| 规则 | 说明 |
|------|------|
| 第 1 行始终是 `__meta__` | 存储会话元信息，以 `__meta__` 键标记 |
| 正序存储 | 最早的消息在前，最新在后 |
| `system` 不写入 | system prompt 不持久化到会话文件 |
| `save_context` 覆写 | 最后一条用户消息可标记 `save_context`，下次加载时作为上下文恢复 |

### 示例数据

```jsonl
{"__meta__": true, "id": "s_abc123", "model": "qwen2.5:32b", "created_at": "2026-06-10T12:00:00", "message_count": 3}
{"role": "user",    "content": "你好，请解释什么是迭代器"}
{"role": "assistant", "content": "迭代器是一种能够遍历数据集合的对象..."}
{"role": "user",    "content": "能否给我一个代码示例？", "save_context": true}
{"role": "assistant", "content": "```python\\nfor i in range(10):\\n    print(i)\\n```"}
```

**`__meta__` 行字段：**

| 字段 | 类型 | 说明 |
|------|------|------|
| `__meta__` | bool | 标记该行为元信息行，固定为 `true` |
| `id` | str | 会话唯一 ID |
| `model` | str | 使用的模型名称 |
| `created_at` | str | ISO 8601 时间戳 |
| `message_count` | int | 消息总数（不含 meta） |
| `forked_from` | str? | 来源会话 ID（分叉时） |

## 记忆文件格式

长期记忆文件位于三来源记忆目录（默认 `~/.local/share/fp/private/memory/`，另有 `public/`、`fetched/` 与项目内 `.fp/memory/`），命名格式 `{name}.md`。每个文件是一份独立的记忆记录。

### 格式：Markdown + YAML frontmatter

```markdown
---
name: user_preference
description: 用户偏好的编程语言和工具链
type: user
created: 2026-06-01
---

用户偏好 Python 和 TypeScript，使用 VS Code 作为编辑器，
熟悉 fastapi、react 和 tailwindcss。
```

### 元数据字段

| 字段 | 必填 | 类型 | 说明 |
|------|------|------|------|
| `name` | 是 | str | 记忆唯一标识名 |
| `description` | 是 | str | 一句话描述 |
| `type` | 是 | str | 类型：`user` / `project` / `feedback` / `reference` |
| `created` | 是 | str | 创建日期（ISO 8601 或 YYYY-MM-DD） |

## 任务文件格式

任务文件位于项目本地 `.fp/tasks.json`，存储**任务图**（taskmap）列表。每个任务 = 一张有向图。

### 格式：JSON（v2）

```json
{
  "version": 2,
  "next_id": 2,
  "maps": [
    {
      "id": 1, "title": "修扬声器", "goal": "扬声器正常出声", "status": "active",
      "nodes": {
        "n0": {"id": "n0", "desc": "(起点)", "kind": "start", "status": "done",
               "owner": null, "dispatch_id": null, "lease_until": null, "evidence": [], "history": []},
        "n1": {"id": "n1", "desc": "扬声器正常出声", "kind": "goal", "status": "pending",
               "owner": null, "dispatch_id": null, "lease_until": null, "evidence": [], "history": []}
      },
      "edges": [{"from": "n0", "to": "n1", "semantic": "requires_decompose", "label": "", "history": []}],
      "questions": [], "refs": {}, "created": 0.0, "updated": 0.0, "next_nid": 2
    }
  ]
}
```

> 旧格式（`{"tasks": [...]}` 线性清单）在读取时**惰性迁移**为 v2：每个旧任务生成一张含起点/目标两节点的图。

### 字段说明

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | int | 任务（图）自增 ID |
| `title` | str | 任务标题 |
| `goal` | str | 目标（验收标准的种子） |
| `status` | str | `active` / `blocked` / `delivered`（待批准）/ `completed` / `superseded`（作废） |
| `nodes` | map | 节点表：`{id, desc, kind, status, owner, dispatch_id, lease_until, evidence[], history[]}` |
| `edges` | list | 边表：`{from, to, semantic, label, history[]}` |
| `questions` / `refs` | list / map | 待澄清问题 / 引用（run_id、产物路径等） |

- **节点** `kind` ∈ `start`/`goal`/`step`/`side_effect`；`status` ∈ `pending`/`active`/`done`/`failed`/`blocked`/`skipped`；`owner`/`dispatch_id`/`lease_until` 为协作**锁**（由唯一写者维护）。
- **边语义**（保留词）：`requires_decompose`/`complete`/`exhausted`/`side_effect`/`blocked`/`partial`。

### 操作

通过任务系统生命周期插件提供的专用工具操作任务图（共 6 个）：`task_create`（建图）/ `task_read`（看全文）/ `task_update`（改元信息）/ `task_edit`（改**图结构**：拆图/加边/改状态/加证据，整批原子）/ `task_list` / `task_clear`。该插件的 `ON_BEFORE_LLM_CALL` 钩子会在每次调用前附加 `[task]` 进度提醒（如 `[task] ▶#1 修扬声器 进行:n2 · 待办:1`；交付待批准时为 `⏸#1 …`）。
