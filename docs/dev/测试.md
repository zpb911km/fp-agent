# 测试

FP 的自动化测试体系，覆盖引擎核心、插件系统与文档防漂移机制。

---

## 定位与策略

测试**不依赖真实 LLM**（mock `_invoke_llm` / `LLMResult` 预设返回），并**隔离文件 I/O**
（临时目录覆盖会话/配置路径），因此可离线、快速、重复运行。

| 原则 | 说明 |
|------|------|
| 🚫 不调真实 LLM | 所有 LLM 交互通过 fixture mock，测的是引擎逻辑而非模型行为 |
| 🧪 隔离文件 I/O | 会话目录、配置缓存全部指向临时目录，**任何测试都不写真实用户数据** |
| 🔍 防文档漂移 | `test_docs_consistency.py` 把源码当权威，校验文档中的数字声明 |
| 🛡 防门禁腐烂 | `test_check_docs_sync_cli.py` 在临时 git 仓库中验证文档同步脚本行为 |

---

## 运行

```bash
python -m pytest -q                 # 仓库根全量（根 pyproject 已登记各包 pythonpath，自洽）
python -m pytest packages/fp-core/tests -q   # 仅核心包
```

全量约 35 秒，输出 `618 passed, 1 skipped`。

> 不依赖 editable 安装指向）。

## 会话隔离（重点）

`tests/conftest.py` 提供四个 **autouse** fixture，对所有测试默认生效：

```python
@pytest.fixture(autouse=True)
def _restore_llm_constants_after_each(): ...  # 还原 config 模块级 LLM_* 出厂常量

@pytest.fixture(autouse=True)
def _reset_config_cache(): ...        # 重置 config 模块 JSON 缓存

@pytest.fixture(autouse=True)
def _isolate_sessions_dir(tmp_path):  # 把 SESSIONS_DIR 指向 tmp_path

@pytest.fixture(autouse=True)
def _isolate_data_dir(tmp_path):      # 把 config._FP_DATA_DIR 指向 tmp_path（隔离三来源资产）
```

**LLM_* 常量还原**：`config.set_active_llm_state()`（/model 热切换入口）用
`globals()` 写 `LLM_ACTIVE_ID / LLM_MODEL / LLM_API_KEY / LLM_EXTRA_BODY` 等
模块常量。若测试调用过它（如 `test_llm_providers`），常量会被污染成"上次激活项"，
殃及同进程后续测试。conftest 在 import 时对九个 `LLM_*` 常量做出厂快照，
每个测试后还原（未定义项删除而非 setattr）。与 `_reset_config_cache` 互补：
后者管 `_json_cfg` 文件缓存，本 fixture 管内存激活态。

**背景**：`Agent.__init__` 无条件创建 `SessionManager` 并写入
`config.SESSIONS_DIR`（`~/.local/share/fp/sessions/`）。早期 `test_agent_tool_parallel.py`
未隔离该目录，导致全量测试在真实会话目录中产生多个测试垃圾会话
（内容形如 `sleep_1/sleep_2`、`test lifecycle`），污染用户会话记录。

**修复**：`_isolate_sessions_dir` 同时 patch 两个引用点：
- `fp_core.config.SESSIONS_DIR`（`agent.py` 中 `os.makedirs` 用的）
- `fp_core.core.session.SESSIONS_DIR`（`SessionManager` 内部用的）

> **新增测试无需额外配置即继承隔离**。若某测试确实需要操作真实会话路径，
> 应在测试内显式 patch，而不是取消全局隔离。

## 防漂移测试（test_docs_consistency.py）

将「源码事实」作为权威，扫描 README 与 `docs/**/*.md`：

- 钩子数 ← `lifecycle.py` 中 `LifecycleHook` 枚举成员数
- 命令数 ← `commands/` 下命令文件数
- 工具数 ← `tools/core.py` 的 `CORE_TOOLS` + extensions + 插件注册

凡出现「N 个钩子/命令/工具」类声明必须与权威值一致；同时检查文档不引用
源码中不存在的命令/工具名（幽灵组件）。任何增删后文档未同步，本测试即失败。

## 文档同步门禁（scripts/check_docs_sync.py）

pre-commit 钩子：**代码变更 → 关联文档跟进提醒**（基于 git diff 变更流，非文本比对）。

- 内容修改（M）→ 只要求「行为描述类」文档（`docs/dev/…`）确认
- 结构变更（增/删/改名）→ 额外要求「清单类」文档（README / guide 参考）确认
- 测试文件（`packages/fp-core/tests/*.py`）变更 → 要求 `docs/dev/测试.md` 确认
- **反向关联（DOC_LINKS，文档 → 代码）**：文档变更时，其登记的关联代码文件
  本次未同步变更 → 输出提醒（**不阻断**，文档允许先行）；`--audit` 会校验
  关联代码文件仍存在（防文档里「源码真相」引用因重构/改名断裂）。
  登记原则：只登记「文档内容明确指向实现」的文档（self 操作指南、dev 行为文档），
  不为纯清单/索引类（README）登记。

```bash
python scripts/check_docs_sync.py                 # pre-commit：检查暂存区
python scripts/check_docs_sync.py --since HEAD~3  # 主动触发
python scripts/check_docs_sync.py --audit         # 审计规则盲区 + 文档关联断裂
```

行为由 `test_check_docs_sync_cli.py` 在临时 git 仓库中逐场景验证。

## 新增测试的规范

1. **优先复用现有 fixture**：mock LLM、`_make_clean_agent`、临时目录
2. **不写真实用户目录**：会话、记忆、任务一律走 `tmp_path`
3. **新增测试文件时**同步更新 `docs/dev/测试.md` 的「测试文件一览」表
   （文档同步门禁会提醒）
4. **全量通过后再提交**：`python -m pytest packages/fp-core/tests -q`

- `test_ask_user.py` — ask 降级/单 flight/回答以 user 角色注入不落 tool result（I2）+ v2 契约（timeout 有界/deferred 不注入/options 透传/事件 schema/ feed_reply 幂等对账）
- `test_jobs.py` — start_job 落盘/完成注入恰好一次/退出清算/stale 清扫/列表合并 + `list_jobs` 硬筛回归（跨会话终态隐藏、活 pid 任务显示、死 pid 清扫后隐藏、running 置顶排序、空 error 字段省略）
- `test_wait_kill.py` — wait 精确等待与超时/kill 进程组/跨重启文件事实
