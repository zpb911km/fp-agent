## `/help` （`/?`）

**功能**：显示所有可用命令及其简短描述。

以排序列表形式输出，每条命令后附有功能说明。此命令的输出也是 Tab 补全菜单的描述信息来源。

输出示例（内置命令见上方速查表；`/model` 为用户级扩展命令，随 fp-ext 分发环境出现）：

```
## 可用命令

- `/back` — 回退到对话的某个历史时刻。用法: /back list 查看列表, /back <N> 直接回退
- `/clear` — 清空当前会话
- `/compact` — 压缩对话历史
- `/exit` — 退出程序
- `/exit!` — 核弹级退出：删除当前会话、不留痕迹
- `/fork` — 基于当前上下文新建会话
- `/help` — 显示此帮助
- `/history` — 查看当前对话历史
- `/model` — 查看/切换 LLM 供应商·模型（两级结构，持久化，重启后保持）※用户级扩展
- `/new` — 新建一个空白会话（保存当前会话后创建全新会话）
- `/option` — 统一管理三种拓展机制（commands / plugins / tools）
- `/reload` — 热重载 Agent（重新加载核心模块，保留会话上下文）
- `/resume` — 切换/删除/清理历史会话。用法: /resume list, /resume latest, /resume <sid|序号>, /resume delete <sid|序号>, /resume prune
- `/session` — 显示当前会话信息
- `/token` — 显示当前会话的 token 消耗统计
```

## `/exit` （`/quit`）

**功能**：正常退出程序。

触发完整关闭流程：

1. 从对话历史中提取最后一条用户消息作为会话摘要
2. 更新会话元数据（摘要标签、消息数等）
3. 保存当前上下文到会话文件
4. 显示退出统计面板
5. 优雅关闭 Agent

### 退出面板示例

```
╔══════════════════════════════════════════════════════╗
║  📂  会话结束                                        ║
║                                                     ║
║  总结: 你好请介绍一下你自己                            ║
║  文件: session_abc123.jsonl                          ║
║                                                     ║
║  📊  统计信息                                        ║
║                                                     ║
║  模型: deepseek-v4-flash                             ║
║  消息: 12 条                                        ║
║  创建: 2026-06-11 20:15:33                          ║
║  耗时: 0:03:45                                      ║
╚══════════════════════════════════════════════════════╝

👋  再见！
```

## `/exit!`

**功能**：核弹级退出，删除当前会话文件，不留痕迹。

该命令不可逆，执行后：

1. 标记核弹退出模式
2. 立即删除当前会话的 JSONL 文件
3. 退出面板**不显示**（因为文件已被删除）
4. 不会生成会话摘要

适宜场景：测试、调试、或不想在系统里留下任何对话痕迹。

> ⚠️ 使用前请确认你不需要保留当前对话。文件删除后无法恢复。

## `/clear`

**功能**：清空当前会话历史。

- 保留系统提示词（system prompt）
- 保留会话 ID
- 仅删除用户消息、AI 回复和工具调用记录
- 等价于重置上下文，但不清除会话元数据

输出：`🧹 当前会话已清空`

---

## `/back`

**功能**：回退到对话历史的某个时刻，删除该位置之后的所有消息。

### 用法

```
/back list              查看历史消息列表
/back <N>               回退到第 N 条消息处（删除后续消息）
```

### 交互示例

```
你 > /back list
📜 对话历史（共 5 条消息，使用 /back <N> 回退）:
  [  1] 👤 用户: 帮我写一个 Python 脚本
  [  2] 🤖 AI: 好的，这里是脚本...
  [  3] 👤 用户: 能加一个错误处理吗？
  [  4] 🤖 AI: 好的，我添加了 try/except...
  [  5] 🔧 工具: 脚本运行结果: OK

你 > /back 3
（已删除消息 4-5，上下文回到消息 3 之后的状态）
```

消息列表按 1-based 编号，仅显示非 system 消息。`/back list` 中每条消息显示角色和内容摘要（超长自动截断）。

## `/history`

**功能**：查看当前会话中的对话历史摘要。

直接在终端中输出当前会话的所有非系统消息，包括角色和内容。

---

## `/fork`

**功能**：基于当前对话上下文创建一个新的会话，并自动切换到新会话。

- 原会话保持不变，带摘要标签保存
- 新会话拥有与当前会话完全相同的上下文（系统提示 + 所有历史消息）
- 后续输入进入新会话

输出：`🍴 已 fork 新会话`

---

## `/compact`

**功能**：压缩对话历史，节省上下文空间。

- 调用 LLM 将较早的消息（除最近 4 条外）压缩为一段摘要
- 压缩后的摘要替换原始消息，显著减少 Token 消耗
- 压缩操作是异步的，执行期间会显示等待反馈

输出：`📦 历史已压缩`

---

## `/sc`

**功能**：短路已完成的连通块，移除工具调用细节，节省上下文空间。

> 注：`/sc` 由 **shortcircuit 插件**在 `ON_INIT` 时通过 `register_command` 注入注册（不走 `commands/` 自动发现）——插件被禁用时 `/sc` 一并消失。

将已完成交互（从用户消息到 AI 最终回复之间的整个回合，含中间工具调用）压缩为精简的 user + assistant 消息对。

### 用法

```
/sc                   短路最近 1 个可压缩态的连通块
/sc N                 短路最近 N 个可压缩态的连通块
/sc list              显示所有连通块概览
/sc #N                短路编号为 N 的连通块（不限形态）
/sc #M-#N             把 #M~#N 当作**一个**跨度处理（闭区间，非逐块）

可选修饰：
  -c                  裁剪(crop)：压成一问一答——只留首条 user + 末条 assistant，
                      中间全丢（含中间插话），不调 LLM
  -r                  提炼(regenerate)：调 LLM 重新生成精简回复
  -d                  退化(degenerate)：删工具调用/返回，保留 AI 文本链
```

### 概念说明

**连通块**：从一条用户消息开始，到 AI 第一次返回不带工具调用的回复结束，中间可以包含多次工具调用循环。这是上下文中最小的语义完整单元。

> `/sc` 是命令语境：**一切块都是历史块，没有「当前块」**——`/sc -c #N` 即使 N 是最后一块也真做 crop。
> 表头出现「当前块#N（只能退化）」只会出现在**工具返回**里（那时 agent loop 正跑到这一步，最后一块正在使用中，只能退化）。

| 形态 | 说明 |
|------|------|
| **可压缩态** | 包含 tool_call/tool 等中间消息，> 2 条，可被短路 |
| **充分压缩态** | 仅 user + assistant 恰好 2 条，已是精简形式 |

### 交互示例

```
你 > /sc list
## 📦 连通块 共3 · 可退化1
`D`=可退化 `C`=可压缩 `~`=已压缩 `*`=未完成｜条数=该块消息数（含工具往返）
- **#1** `D` 4条 · 帮我查天气 ｜ AI: 北京25°C...
- **#2** `~` 2条 · 谢谢 ｜ AI: 不客气
- **#3** `C` 6条 · 写个脚本处理 CSV ｜ AI: 已生成 output.py

你 > /sc
🔄 正在短路...
 ✅
✅ crop #3 · 消息 12→8 条（省 4）｜剩余可退化 #1

你 > /sc #1 -r
🔄 正在短路...
 ✅
✅ regenerate #1 · 消息 8→6 条（省 2）｜剩余可退化 无
```

结果行是**对账**：动作 + 块编号 + 实测条数变化 + 剩余可退化编号。
若前后条数相同，会变成警告而非成功：

```
⚠️ crop #2 · 消息 2→2 条（省 0）｜剩余可退化 无
未剪到任何消息：目标块已无中间过程/工具往返可删——换块，或换 mode（只有 degenerate 能清工具往返）
```

### 行为要点

- `/sc` 和 `/sc N` 只作用于**可压缩态**连通块，已充分压缩的自动跳过
- `/sc #N` 不限形态，regenerate 模式下也可重新提炼已充分压缩的回复
- 支持多次短路同一个连通块（regenerate 模式可反复提炼）
- 失败的提炼操作会触发**原子回滚**，上下文不受影响
- 底层通过 `ConversationState.scan_components()` 检测连通块边界，无需显式标记

## `/resume`

**功能**：切换或删除历史会话。支持多种用法。

### 用法

```
/resume                   列出所有会话（无参数 = list）
/resume list              列出所有会话（subagent 会话带 🔹 标记）
/resume --main            只看主会话（过滤 subagent 子任务会话）
/resume latest            切换到最新会话（按更新时间）
/resume <sid|序号>        切换到指定会话（支持 list 中的序号）
/resume list <词...>      按标题/关键词/sid/cwd 筛选（不读正文，秒出）
/resume -f <词...>        按正文内容搜索（扫全库约 300ms，多词之间为 AND）
/resume <词...>           非 sid/序号时自动按正文搜索（= /resume -f 的简写）
/resume delete list       列出可删除的会话
/resume delete <sid|序号> 删除指定会话
/resume prune             清理 0 长度会话文件（移到 .trash/，不真删）
```

### 交互示例

```
你 > /resume
## 📂 会话列表
使用 `/resume <sid>` 切换，`/resume latest` 切换到最新
`[subagent]` = 子代理任务会话，`/resume --main` 只看主会话

- **[1]** 🔹 [subagent] 分析 ELF 文件 (5条, `s_260710_120000123456`)
- **[2]** 帮我搜索 Python 异步编程... (8条, `s_260610_153022123456`) ⬅
- **[3]** 写一个排序算法... (12条, `s_260609_090011654321`)

你 > /resume --main
## 📂 主会话列表（已过滤 subagent）
- **[1]** 帮我搜索 Python 异步编程... (8条, `s_260610_153022123456`) ⬅

你 > /resume 1
📂 已切换到会话: s_260610_153022123456
```

- 当前正在使用的会话以 `⬅` 标记
- 🔹 / `[subagent]` 前缀 = subagent 子代理任务会话（自动创建）
- 切换支持 sid 或列表序号；当前会话不可以删除
- `/resume list <词>` 只看元数据（标题/关键词/sid/cwd、秒出）；要搜**正文**用 `/resume -f <词>`
- 输入的内容既不是序号、也不是存在的 sid 时，自动降级为正文搜索——不会只回一句
  「会话不存在」让你猜语法
- 切换会话后上下文会重建为对应会话的状态
- 列表的摘要列保证可读：老会话缺 `summary` 时按文件里最后一条用户消息回填，
  摘不出给 `(无摘要)` / `(空白会话)`，不会退化成 sid
- 正文没有任何消息行的 0 长度会话不进列表（当前会话除外）；历史遗留用
  `/resume prune` 批量清到 `.trash/`（移动，不删除）

### 正文搜索（`/resume -f <词...>`）

**功能**：按**会话正文内容**搜索历史会话。会话多了以后，标题只记着「推送」「ok」
这类无信息内容，找会话时你记得的往往是**聊过什么**——这个命令就搜那个。

#### 用法

```
/resume -f <词...>   搜索正文（多词之间为 AND，逐词收窄）
```

#### 检索范围

- ✅ `user` 正文、`assistant` 正文
- ✅ 标题、关键词、sid、cwd（元数据命中也会列出，片段为空）
- ❌ **`tool` 返回值一律不搜**——它占全部语料的 50%，放进来搜任何词都会命中一堆
  日志转储，把真正的对话淹掉
- ❌ reasoning / 系统注入块不搜

#### 交互示例

```
你 > /resume -f 量子
## 🔍 `量子` — 命中 3 个会话（正文 3，仅标题/关键词 0）
用 `/resume <序号>` 直接切换；序号与 `/resume list` 一致
- **[81]** OK了 · 索引 合并 检索 (73条)
      🤖 `…每次写入沿叶→根逐层重算聚合，3 层就是 3 次合并…`
- **[193]** 对的。反正现在这个东西是已经阻碍了自举了… (43条)
      👤 `…**范畴论**提供交互的**组合结构**（幺半范畴、紧闭范畴——量子力学和计算共用的数学）…`

你 > /resume 81
📂 已切换到会话: s_261009_203820519984
```

#### 设计要点

- **序号与 `/resume list` 共用同一个排序池**：搜到的序号可直接 `/resume <n>` 切换，
  这是「搜到 → 跳过去」一步到位的前提
- 命中片段取关键词前后各约 40 字，用来一眼确认「是不是这条」
- 实现是**实时扫描**（ripgrep 粗筛 → 解析 JSONL 精确判定），不建倒排索引：
  906 个会话 / 309MB 全库一次搜索约 300ms，索引的维护成本远高于这个开销
- `rg` 不可用时自动退化为纯 Python 扫描（约慢 10 倍，功能等价）

## `/option` （`/opt` `/op` `/ext` `/extension` `/extensions`）

**功能**：统一管理三种拓展机制（commands / plugins / tools）。

```
/option                    → 等同 /option list

```

> 对应"文件即开关"机制：`.disabled` 后缀 = 禁用。

/reload modules      仅重载模块，不创建新 Agent（调试用）

## `/task`

**功能**：任务图（taskmap）控制台 —— 看、开、清，以及**人特有的权力**：批、答、停。

> 注：`/task` 由 **task_system 插件**在 `ON_INIT` 时通过 `register_command` 注入注册（不走 `commands/` 自动发现）——插件被禁用时 `/task` 一并消失。

每个任务是一张**有向图**：节点 = 须成立的状态，边 = 带结果语义的转移。它是长任务的**脊柱**（目标、计划、进度、协作锁），`agent_dispatch` 是执行其节点的**手**。

### 用法

```
/task                     列出所有任务
/task show <id>           全文（契约/节点/边/待澄清）
/task view <id>           看图（终端出树形，其余前端出 mermaid）
/task view <id> --mermaid|--tree   强制指定呈现
/task new <标题>           新建任务
/task approve <id>        批准交付 → completed
/task reject <id> [原因]   打回 → active（原因记入待办）
/task answer <id> <q#> <文本>    回应待澄清（解 agent 的 blocked）
/task pause <id> / resume <id>   暂停 / 恢复
/task abort <id>          作废 → superseded
/task clear               清除终态任务（已完成/已作废）
```

### 交互示例

```
你 > /task
**任务列表**
- `#117` **[进行中]** 任务图可视化 + /task 控制台  （节点 2 · 待办 1）

你 > /task view 117
#117 任务图可视化 + /task 控制台  [进行中]
目标: ...
✅ n0 (起点)
└─ ⬜ n1 任务图可视化 + /task 控制台  [requires_decompose]
```
