# 记忆系统

## 什么是记忆

记忆系统提供**跨会话持久化**存储能力。普通的会话上下文在每次交互结束后就会丢失，而记忆可以将关键信息保存下来，在未来的会话中重新读取。

**存储位置（双根树）**

```
全局：~/.local/share/fp/{fetched,public,private}/memory/{分类}/{name}.md   ← 三来源合并，private 胜
本地：./.fp/memory/{分类}/{name}.md                                       ← 项目内（cwd），git 忽略
```

记忆按**树布局**组织：每个分类是一个子目录，每条记忆是其中一个 Markdown 文件（文件名即记忆名）。

---

## 记忆格式

每个记忆文件使用 **YAML frontmatter + Markdown 正文** 的格式。

**YAML frontmatter 字段**

| 字段 | 说明 |
|------|------|
| `name` | 记忆唯一标识名（英文短词） |
| `description` | 一句话描述，用于检索 |
| `type` | 分类（与所在目录一致：user/project/feedback/reference/skill …） |
| `created` | 创建时间戳 |
| `updated` | 更新时间戳（保存时刷新，`created` 保留原值） |
| `hint` | 可选：短硬事实（存储上限 80 字符，level-0 热键展示截断到 40） |
| `context` | 可选但强烈建议：何时/何地/何种范围成立——缺它换个会话就不知所云 |

**完整示例**

```markdown
---
name: user_role
description: 用户的角色和偏好信息
type: user
created: 2026-06-10T15:30:00
updated: 2026-06-10T15:30:00
context: 长期成立，适用于所有协作场景
---

用户是一名全栈开发者，主要使用 Python 和 JavaScript。
偏好简洁的代码风格，注重文档质量。
```

## 两级索引（派生缓存）

树结构自带两级**机器生成**的索引文件，均可丢弃重建：

- `_index.md`（level-0，根）：类别清单 + 条数 + 一行用途 + 热键 + 用法提示。**构建会话时生成一次并注入系统提示词**（约 1.2KB，且会话内冻结以保护前缀缓存）
- `_node.md`（level-1，每类）：该类子条目的一页摘要（一行一条）+ 逃生舱提示

两者都是**派生缓存**：内容过期（子条目比它新）才重写——**你手动编辑过的索引文件机器不会覆盖**（手动优先）。

## 管理记忆

### 保存记忆

通过 `memory_save()` 工具保存记忆。

```python
memory_save(
    root="~",            # "~" 全局 / "." 项目本地
    category="project",  # 分类目录
    name="project_goal",
    description="当前项目的核心目标",
    content="开发一个 AI Agent 框架，支持技能插件和会话管理",
    context="2026 下半年主目标",     # 建议提供
    hint="目标=技能插件+会话管理"      # 可选，短硬事实（热键展示截 40 字符）
)
```

保存时自动：写入分类目录 → 刷新该类 `_node.md` 与根 `_index.md` → 更新全文检索索引。

### 读取记忆

通过 `memory_read()` 工具读取，五个入口：

```python
memory_read()                              # ① level-0 根索引（类别+热键）
memory_read(name="user_role")              # ② 精确读取（带访问计数与过期提醒）
memory_read(path="~/skill")                # ③ 下钻某分类（level-1 摘要页）
memory_read(query="wifi 断网自动登录")      # ④ 搜索：FTS5 排序 + AND + 打分三段兜底
memory_read(all=True)                      # ⑤ 全量一行摘要（逃生档）
```

**搜索语义**：先走 FTS5 全文排序，未命中退 AND 子串，再未命中退 bigram 打分（中文自然语言查询也能捞到）。仍无结果时返回值里会**内嵌升级指引**——必须走 `all=true` 全量扫描后才准报告"没有这条记忆"，不允许静默失败。

**升级路径（查不到时）**：`query` → `path` 浏览相邻分类 → `all=true` 全量扫描。

### 过期与提醒

`updated` 超过 30 天的记忆，精确读取时会附带 ⚠️ 过期提醒；**使用前先验证**。

## 分类

`type` 即目录名。全局常用：`user` / `project` / `feedback` / `reference` / `skill` / `communication`；项目本地常用：`project` / `fix` / `skill` / `architecture` / `charter` 等。分类目录可按需新建；禁用分类：`core` / `misc` / `other` / `uncategorized`（会进 lint 报告）。

选择正确的分类有助于下钻浏览时快速过滤——但**分类不是唯一入口**：`query` 全文检索与 `all=true` 扫描永远兜底，放错抽屉的记忆也能被捞回来（错抽屉会被巩固检测持续报告）。

## 巩固检测（自动）

插件 `memory_consol` 在启动时（日频、幂等）跑一次机检并输出到 `{DATA}/journal/`：

- **报告** `memory_report_YYYYMMDD.md`：分裂建议（单类 >20 条）、合并建议（<4 条）、近重/疑似冲突（description 相似度 ≥0.6）、孤儿（90 天零访问）、过期（90 天未更新）、错抽屉（目录与 `type` 不符）、禁用分类、缺 `context`
- **journal** `memory_consolidate.jsonl`：逐条结构化记录（供后续 LLM 复核执行搬迁/合并）

检测只报告不动手；结构搬迁类操作由 LLM 复核报告后执行（`scripts/migrate_memory_tree.py` 提供批量搬迁与回滚能力）。
