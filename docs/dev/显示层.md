# 显示层

显示层负责所有面向用户（终端）的输出，涵盖 LLM 流式输出、日志、旋转动画和系统仪式感提示。

---

## 6 类输出函数

所有输出样式（颜色、标记）均从 `~/.config/fp/config.json` 的 `display_styles` 和 `display_truncation` 读取。

| 类别 | 函数 | 用途 |
|------|------|------|
| **A. 操作反馈** | `info(msg)` / `item(label, msg)` | 信息提示、分项展示 |
| **B. 行为提示** | `hint(msg)` | 引导用户下一步操作 |
| **C. 异常警示** | `error(msg)` / `warning(msg)` | 错误与警告输出 |
| **D. LLM 流** | `llm_thought(text)` / `llm_tool(text)` / `llm_output(text)` / `llm_newline()` / `llm_iteration(label)` | 流式渲染 LLM 思考、工具调用、最终回复 |
| **E. 系统日志** | `debug(msg)` | 调试级输出，受 config 中 debug 开关控制 |
| **🎨 仪式感** | `startup()` / `shutdown_panel()` / `print_logo()` | 启动/关闭时的品牌展示 |

实现位于 `packages/fp-terminal/src/fp_cli/display.py`，所有函数最终调用底层 `_styled_write(style, text)`。

## LLMStreamer

`class LLMStreamer` 负责逐块接收 LLM 输出并渲染到终端。

```
class LLMStreamer:
    def think(self, text: str):     # 渲染思考片段
    def write(self, text: str):     # 渲染输出片段
    def end(self, interrupted=False): # 结束流（interrupted=True 表示被中断）
```

- 每次 `think()` / `write()` 调用立即刷新到 stdout。
- `end()` 负责清理尾部状态（如关闭 spinner、输出换行）。
- 中断模式下保留已输出内容，仅标记终止。

---

## Spinner

`class Spinner` 提供后台旋转动画，用于耗时操作的视觉反馈。

```
class Spinner:
    def start(self):   # 启动动画线程
    def stop(self):    # 停止并清理
```

- 动画帧序列从 `~/.config/fp/config.json` 的 `display_styles.spinner_frames` 读取。
- 所有终端输出前自动暂停 spinner，输出后恢复。

## 问答块渲染（ask v2）

`CLIIO.ask()`（`cli_io.py`）在终端渲染结构化问题块并解析输入：

```
❓ <问题>
   1. <选项A>
   2. <选项B> （推荐）
   💡 推荐默认值：n（直接回车采纳）
❯ 
```

解析规则（展示层负责，返回的已是最终文本）：
- **空回车** → 采纳 `suggest`（无 suggest → 空串 = 未回答，不伪造）
- **编号 1..N** → 对应选项原文；越界编号按自由文本原样返回
- **其他** → 自由文本原样；EOF/Ctrl+C → 空串

**显示时序（防挤占回答区）**：`tool_call`/`tool_result` 展示是
`create_task` 异步调度（含逐段 0.02s 流式延迟），会插进问题块与输入
光标之间。`ask()` 两段防护：① 渲染前 `asyncio.wait` 已入队的展示任务
（工具参数行先落盘）；② 持 `LLMStreamer._get_tool_lock()` 渲染问题块并
读输入 —— 问答挂起期间新到的工具行在锁外排队，答完按序打印。

测试：`packages/fp-terminal/tests/test_cli_ask.py`（含 2 个时序回归用例）。

## 配置驱动样式

所有颜色/标记/截断长度均不硬编码：

```json
{
  "display_styles": {
    "info":     { "color": "cyan", "prefix": "ℹ" },
    "error":    { "color": "red",  "prefix": "✗" },
    "thought":  { "color": "green", "prefix": "◆" },
    "spinner_frames": ["⠋","⠙","⠹","⠸","⠼","⠴","⠦","⠧","⠇","⠏"]
  },
  "display_truncation": {
    "tool_output_max_len": 2000,
    "thought_max_len": 500
  }
}
```

代码中通过 `get_style(key)` 和 `get_truncation(key)` 访问。

## TUI 交互模式（L0，Textual）

交互主前端是 `packages/fp-terminal/src/fp_cli/tui.py` 的 Textual 应用（`FPApp`）：
常驻多行输入区（`PromptInput`，TextArea 子类 + 发送按钮）+ 可滚动消息历史区，
边流式输出边可输入（运行中输入经
`portal.run.submit()` 排队穿插，见 `docs/dev/唯一接口组协议.md`）。

**输入区视觉**（极简方案，设计者 glm-5.3）：`#prompt_row` 只留上下两条
`tall $surface` 细线、无背景无左右边框——注意 border 属性只接受单 token 色，
`$text-muted`（展开为 `$text 60%`）会解析失败；输入框 `height: auto +
max-height: 6` 随内容增长；发送钮无文字（`↑` 图标，宽 3）以
`height: 100%` 与输入框精确对齐。度量陷阱：Textual 8.x 的 `size` 是内容区，
含边框的真实渲染高度看 `region`。

**三层降级链**（`tui_available()` 判定，L0 失败逐级下沉，急救场景砖不了）：

| 层 | 条件 | 路径 |
|----|------|------|
| L0 TUI | 无 `FP_NO_TUI` / 非 subagent / stdin+stdout 均 TTY / `TERM != dumb` / textual 可导入 | `FPApp.run_async()` |
| L1 经典 REPL | 以上任一不满足 | 裸 `input()` 循环（`main.py` `_read_line`，无补全/历史） |
| L2 无头 | `--headless` / `-m` 单发 / 管道 | 不进交互前端，CLIIO 打印通路 |

- **IO 分流在 `ctl.open(io=)` 之前**：`TUIIO`（输出经消息队列进 widget，
  裸 print 会砸屏）vs `CLIIO`（直接打印）。TUI 模式下 core 日志经
  `set_logger(TUILogger)` 改走同一通道。
- **流式渲染**：`TUIIO` 收流式片段 → 同一 `Markdown` widget 节流 `update`
  （同一 block 不重复 mount）→ 轮末固化进历史区。
- **键位**（`FPApp.BINDINGS` + `PromptInput.BINDINGS`）：`Enter` 换行 /
  `Shift+Enter`、`Ctrl+J` 或**发送按钮**提交（优先级绑定，modal 打开时不抢；
  运行中排队；`Ctrl+J` 是 `Shift+Enter` 的终端兜底——不支持 kitty 键盘协议的
  终端会把 Shift+Enter 退化成 CR，与 Enter 字节不可区分，而 LF 全终端可区分）
  / `Ctrl+C`、`Ctrl+Shift+C` 三分支：有选区（输入框内建选区，或聊天区鼠标
  拖选的屏幕级选区）→ OSC52 复制，忙碌无选区 → 打断，空闲无选区 → 通知提示
  **不退出**（防复制误触；退出统一 `Ctrl+Q`）/ `Ctrl+G` 统计 / `Tab` 补全菜单；
  `↑↓` 按光标位置分流——未到行边界只移光标；`↑` 到首行再按翻上一条历史
  （落其最后一行，可继续逐行上溯）、`↓` 到末行再按翻下一条（落其第一行，
  可继续逐行下行）；空输入即单行，`↑↓` 直接浏览历史（子类绑定确定性实现，
  不依赖按键冒泡）。
- **busy 语义**：运行中提交走 `submit()` 排队（⏳ 回显），运行中斜杠命令
  被 core 守卫就地拒绝（不入队、不喂 LLM）。
- **#6643 竞态修复**：默认屏为 `FPDefaultScreen`——`Markdown.update()`
  摘块窗口内点击，compositor 命中图可能仍指向已 detach 的段落块，
  原生 `Screen._forward_event` 取 `parent=None` 会崩（上游
  Textualize/textual#6643，PR #6645 未合并、8.2.8 仍带病）。
  `get_widget_and_offset_at` 将 detached 命中降级为 miss（等价上游修法，
  回归测试 `TestDetachedHitRace`）；上游发布修复版本后可退场。

## 斜杠补全（输入侧）

词表逻辑收编在 `packages/fp-terminal/src/fp_cli/completion.py` 的纯函数
`slash_matches(text)`（TUI 与测试共用）：从 `portal.run.commands`
（即 `fp_core.commands.get_all_commands()`）取命令词条（含描述），
TUI 的 `Tab` 弹补全菜单、输入 `/` 时下方显示匹配提示。

- **惰性现查**：每次匹配都重新拉注册表、不缓存词表。
  原因：命令词表可能滞后于命令注册的变化（历史上的 `/reload` 是同进程原地重建、
  不重建补全器；现已是进程级 execve 重启，但同进程的插件热启停与
  WebUI REST 重载仍会让缓存词表过期）。惰性刷新让命令变化**立即可补全**，
  注销后也立即消失。
- 仅当输入以 `/` 开头时才匹配（普通文本不触发）。
- prompt_toolkit 及其 `SlashCompleter` 已于 n10 退场；输入历史由
  `history.py` 持久化（**与 prompt_toolkit FileHistory 格式兼容**，旧历史文件直接沿用）。

## 无头驻留模式（--headless）

`fp_cli/main.py` 的 headless 分支**不进任何交互前端**（L2）：TUI、L1 提示符、
输入历史、Tab 补全（含上一节的 `slash_matches`）全部不启用，logo 也不打印，
只留一行驻留提示（含 session id）。

- **退出条件只有信号**：交互模式 `input()` 读到 EOF（后台无 pty 启动）即 break 退出，
  实例当场死亡、zeta 名片失效；headless 把「没有输入」视为常态，stdin 是否可读、
  是否已 EOF 都不影响存活，`SIGINT`/`SIGTERM` 才收尾——与 REPL 走同一套
  `ctl.close()` → 统计面板 → 保存会话。
- **输出改行缓冲**：stdout/stderr 重定向到文件时默认块缓冲，驻留进程的日志会攒到
  退出才落盘（而它恰恰到收到信号才退出，等于永远看不到）。启动时对带
  `reconfigure` 的流开 line buffering，让日志实时可见。
- **续接照常消费**：热重启 handoff 仍由 `take_reload()` 取走并执行，
  区别只是完成后落入驻留循环，而非 REPL 输入提示。
- **subagent 标记不落空文件**：`FP_IS_SUBAGENT=1` 的子进程在入口把
  `source` / `parent_sid` 写进**内存 meta**（`update_meta(create=False)`），
  随首条消息一起落盘；没产出内容的子会话因此不留下 0 长度会话文件，
  父进程的 `_finalize_subagent_session` 也只收尾**已落盘**的子会话。

## 热重启续接渲染（三入口）

工具面（`reload` 携口令）与命令面（`/reload`，人触发免口令）共用激活核心
`handoff.perform_exec_reload`，落盘 handoff `{sid, ts, frontend, kind}` 后
execve 重启。新实例三入口统一消费 `consume_reload_handoff` 并按 kind 分流：

- **kind=tool**：`state._pending_continue` 置位 → `continue_conversation(io=本入口IO)`
  → 渲染 Response → 置回 `None`；
- **kind=command**：`state._reload_notice` 置位 → 入口显示一行「🔄 热重启完成，
  会话 xxx 已恢复」→ 置回 `None`，回到正常输入（无挂起工具轮，不进续接）。

| 入口 | 续接与渲染方式 |
|------|----------------|
| **fp-terminal** | REPL 外层消费续接，经既有输出通道渲染 |
| **fp-webui** | lifespan 续接；事件进 EventBus 环形缓冲，客户端凭 `run_id` resync；并发由 `is_running` 拦截 |
| **fp-acp** | session/prompt 挂起的 req id 记 `FP_ACP_PENDING_REQ`，续接后补发 chunk + result |
