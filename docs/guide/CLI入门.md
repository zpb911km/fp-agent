# CLI 入门

FP 的主交互方式是通过命令行界面（CLI）。本文档涵盖基本用法、命令行参数、快捷键和中断处理。

---

## 基本用法

```bash
# 进入交互模式
fp
```

交互模式下，终端显示提示符 `(Agent) > `，用户可直接输入文本消息与 AI 对话，或以 `/` 开头的斜杠命令控制系统行为。

---

## 命令行参数

`fp` 的参数分三层，完整清单可用 `fp -h` 查看：

**① 顶层参数**（由 `fp` 入口消费，决定分发行为）

| 参数 | 说明 |
|------|------|
| `--mode {cli,webui,acp}` | 启动模式，默认 `cli`。短写 `-m` 仅当取值为三个模式名时等价 |
| `--model <spec>` | 覆盖本次激活模型：`provider/model` 精确形式，或 `LLM_PROVIDERS` 表内裸模型名（激活 provider 优先、全表唯一命中次之；查无/歧义则回退配置激活项并告警） |
| `--session <SID>` | 恢复指定会话，等价于 CLI 的 `-r <SID>`；webui/acp 模式同样生效 |
| `--docs` | 查看离线文档（等价 `fp docs`） |
| `--version` / `--update` | 显示版本号 / 检查并升级**本地已安装**的 fp 组件（缺失的包不强装；逐包执行，单包失败不阻塞其余） |

**② 透传给 CLI 模式的参数**（顶层原样转发，由 `fp_cli` 解析）

| 参数 | 完整形式 | 说明 |
|------|---------|------|
| `-m <msg>` | `--message <msg>` | 单次消息模式。发送一条消息后直接退出，不进入交互循环 |
| `-r` | `--resume` | 恢复最新会话。不加参数值则自动恢复最新的历史会话 |
| `-r <SID>` | `--resume <SID>` | 恢复指定 ID 的会话 |
| `--headless` | — | 无头驻留模式。跳过 logo 与交互提示，启动即常驻，直到 `Ctrl+C`/`SIGTERM`；无 pty、stdin EOF 都不会导致退出。可与 `-r` 组合 |

> **`-m` 的双义规则**：取值是 `cli|webui|acp` 之一 → 视为 `--mode`（选启动模式）；
> 其他取值 → 视为 `--message`（单次消息）。例如 `fp -m webui` 启动 Web 界面，
> `fp -m "你好"` 发送单条消息。

**③ 子命令**（在顶层解析前路由，参数互不干扰）

| 子命令 | 说明 |
|--------|------|
| `fp docs [路径\|--list\|--path\|--open]` | 离线文档查看，详见 `fp docs` |
| `fp ext <子命令>` | 扩展资产分发（fetch/install/review/list/…），详见 `fp ext -h` |

## 示例

### 1. 交互模式

```bash
fp
```

进入交互界面，显示启动 Logo 和提示信息，用户可连续输入消息。

### 2. 单次消息模式

```bash
fp -m "你好"
```

发送消息后自动退出，适合脚本调用或快速测试。

### 3. 恢复最新会话

```bash
fp -r
```

或完整形式：

```bash
fp --resume
```

自动加载最近一次保存的会话上下文，继续之前的对话。

### 4. 恢复指定会话

```bash
fp -r session_abc123
# 或等价的顶层写法
fp --session session_abc123
```

### 5. 配置 LLM 连接

```bash
# 直接运行 fp；缺配置时自动进入交互式配置向导
fp
```

`LLM_API_KEY` / `LLM_API_BASE_URL` / `LLM_MODEL` 三项均为必填、无内置默认值。
也可编辑 `~/.config/fp/config.json` 或设置同名环境变量。

### 6. 无头驻留模式

```bash
# 常驻（后台/管道/服务管理器拉起均可，无需 pty）
fp --headless

# 常驻并恢复指定会话
fp --headless -r session_abc123
```

不进入交互循环，启动即常驻：邻居铃声、注入事件照常处理，`Ctrl+C` 或 `SIGTERM` 才退出（退出走正常收尾：保存会话、统计面板）。
与交互模式的关键差异——交互模式在 stdin 读到 EOF（后台无 pty 启动）时会直接退出，驻留模式把「没有输入」视为常态，因此不再需要 `screen`/`tmux` 包一层。

输出重定向到文件时自动切换为行缓冲，日志实时可见。

## 快捷键

| 快捷键 | 功能 |
|--------|------|
| `Enter` | 输入框内换行（多行输入） |
| `Shift+Enter` 或 **发送按钮** | 发送输入（TUI；运行中发送则排队穿插，显示 ⏳ 已排队） |
| `Tab` | 补全。输入 `/` 后按 Tab 把**当前选中**候选插入输入框（上方浮层实时显示候选与其用法，见下文「Tab 补全详解」） |
| `Ctrl+C` | 复制选区（输入框内或聊天区鼠标拖选 → OSC52 写入系统剪贴板）；无选区时只提示，**不退出**（退出用 `Ctrl+Q`）。它**只做复制**——打断是另一个独立动作，默认未绑键 |
| `Ctrl+Q` | 退出程序，触发正常退出流程（生成总结、统计面板、保存会话） |
| `Ctrl+K` | **键位设置面板**的开关（再按一次关闭）：选中动作按 `Enter` 进入捕获、按新键即改（立即生效并写回 `tui.keys`），`R` 恢复当前项（回出厂键）、`Delete`/`Backspace` 取消绑定（动作保留但没键）、`Ctrl+R` 全部恢复、`Esc` 关闭。键位配坏或终端认不出它时，用 `fp --keys` 兜底 |
| `↑` / `↓` | 浏览输入历史（`history.py` 持久化，与 prompt_toolkit FileHistory 格式兼容，旧历史沿用）：光标未到行边界时只移动光标；`↑` 到**首行**再按 → 上一条历史（光标落其最后一行，可继续逐行上溯），`↓` 到**末行**再按 → 下一条历史（光标落其第一行，可继续逐行下行）；空输入即单行，直接按 `↑`/`↓` 翻历史。**斜杠补全浮层打开时 ↑↓ 归浮层选候选**，要翻历史先按 `Esc` 关浮层 |

**其余动作默认都不绑键**——消息区滚动、卡片导航与开合、统计、外观、**打断**（中断运行中的操作）、以及输入框内的
编辑动作（行首/行尾、删行、删词、剪切粘贴撤销…），出厂一律留空，由你在 `Ctrl+K`
面板里按自己的手感设。一个动作只绑**一个**键（不支持多别名），所以不会出现「这个键
到底归谁」的歧义。

这样设计的理由：给谁分配默认键都是替用户拍板，而键位偏好因人而异（尤其
`Ctrl+U`/`Ctrl+D`/`Ctrl+E` 这类 readline 惯用键，占了就等于抢走输入框编辑能力）。
留空 + 面板自设是唯一不冒犯任何人的默认。

两个例外值得知道：

- 输入框编辑动作**未设键时走 TextArea 自带键位**（`Ctrl+A`/`Ctrl+E`/`Ctrl+U`/`Ctrl+D`/
  `Ctrl+W`/`Ctrl+X`/`Ctrl+V`/`Ctrl+Z`/`Ctrl+Y` 等照常可用）——面板里显示「（未绑定）」
  指的是*我们这套键位体系*里没绑，组件自带的不受影响。你在面板里设了键就覆盖它。
- 上表这些键都是**基线**：`Shift+Enter` 没有就没法发送、`Ctrl+Q` 没有就退不出、
  `Ctrl+K` 没有就进不了面板。它们是唯一保留的默认值。全部可在面板里改。

两个限制来自终端协议本身，不是 fp 的选择：

- **`Ctrl+I` 绑不上**：它和 `Tab` 发的是同一个字节 `0x09`，终端与 fp 都无法区分。同样情形的还有
  `Ctrl+M`≡`Enter`、`Ctrl+[`≡`Esc`、`Ctrl+H`≡`Backspace`、`Ctrl+J`≡换行、`Ctrl+/`≡`Ctrl+_`。
  这类别名会归一到实际收到的键名，并在改键时如实告诉你。
- **`Ctrl+Q` 是唯一保留键**：捕获时按它视为「退出捕获」而不写盘。丢了它就退不出程序，且没有替代；
  其余键（包括 `Ctrl+C`）你都可以随意改动、也能改回来。


`config.json` 的 `tui.keys`（按动作 id），或用 `Ctrl+K` 面板改。

```bash
fp --keys          # 启动即打开键位面板；无 TTY 时直接打印键位表
```

`fp --keys` 不经过 TUI 内任何键位绑定，所以**键位配坏、或终端认不出快捷键时它是
唯一可靠的入口**。外壳不占用 `/` 斜杠命名空间（那是 agent 与插件的命令注册表）。

## Tab 补全详解

输入 `/` 前缀时，输入框上方弹出**补全浮层**：左边是候选命令窗（一屏 6 条，选中行反显并带
`❯` 光标），右边是选中命令的帮助栏（命令名、别名、一行描述、「用法:」正文，按栏宽自动折行）。
终端窄到放不下两栏时自动切成上下叠放。

1. 输入 `/resume` 前缀 — 浮层列出匹配的命令，**右侧同步显示第一条的用法**
2. `↑` / `↓` — 在候选间移动，右侧帮助随之切换（光标停在输入框首/末行也优先给浮层）
3. `Tab` — 把**当前选中**项插入输入框（补全后浮层自动收起）；`Esc` — 只关浮层，正文不动，继续输入会重开

帮助栏内容分两层来源：一行描述取自命令模块的 `description`；「用法:」正文从命令模块
docstring 的 `用法:` 小节里抽（没有就不显示），docstring 的其余部分是实现注记，**不进浮层**。
所有正文按终端实际栏宽折行（CJK 记 2 格），超出上限时在末行前插 `…` 而不是静默截断。

补全列表从命令系统**惰性现查**（`fp_cli.completion.slash_candidates`，每次重新拉注册表、不缓存），
`/reload` 或插件热启停后新命令立即可补全。

## Ctrl+C 中断处理

FP 采用双保险中断机制，确保在任意状态下中断操作而不会导致数据损坏。

### 中断机制的层级

**层级一（Unix 主线程）**：通过 `signal.signal(signal.SIGINT, _raw_sigint_handler)` 安装纯 C 级信号处理器。信号到达时调用 `asyncio.all_tasks().cancel()` 注入 `CancelledError`，由各协程的 `try/except` 优雅捕获。

**层级二（跨平台回退）**：设置全局标志 `_interrupted_flag = True`。此标志在 Windows 等平台上作为安全网——`_check_interrupted()` 方法在 Agent 主循环的每次迭代中检查该标志，若置位则抛出 `CancelledError`。

### LLM 思考中中断

当 LLM 正在生成回复流时按下 `Ctrl+C`，中断会捕获已经生成的内容并保留到上下文中。LLM 回复中的 `tool_calls` 会被标记为中断状态，已生成的文本内容不会被丢弃。

```python
# 中断后的处理逻辑
if interrupted:
    display.info("⏹️ 已中断（保留了已生成的内容）")
    break
```

### 工具执行中中断

当 Agent 正在依次执行多个工具调用时按下 `Ctrl+C`：

- 当前正在执行的工具被标记为"工具调用失败：用户中断"
- 其余尚未执行的工具均标记为"未执行（工具调用失败：用户中断）"
- 所有工具调用信息保留在上下文中，Agent 不会丢失状态

```python
except (KeyboardInterrupt, asyncio.CancelledError):
    self._conv.add_tool_message(tc["id"], "工具调用失败：用户中断")
    for remaining in tool_calls[i + 1 :]:
        self._conv.add_tool_message(remaining["id"], "未执行（工具调用失败：用户中断）")
    break
```
