# 显示层

显示层负责所有面向用户（终端）的输出，涵盖 LLM 流式输出、日志、旋转动画和系统仪式感提示。

---

## 6 类输出函数

所有输出样式（颜色、标记）均从 `~/.config/fp/config.json` 的 `display_styles` 和 `display_truncation` 读取。

| 类别 | 函数 | 用途 |
|------|------|------|
| **A. 操作反馈** | `info(msg)` / `item(label, msg)` | 信息提示、分项展示 |
| **B. 行为提示** | `hint(msg)` | 引导用户下一步操作 |
| **C. 异常警示** | `error(msg)` / `warning(msg)` | 错误与警告输出 |
| **D. LLM 流** | `llm_thought(text)` / `llm_tool(text)` / `llm_output(text)` / `llm_newline()` / `llm_iteration(label)` | 流式渲染 LLM 思考、工具调用、最终回复 |
| **E. 系统日志** | `debug(msg)` | 调试级输出，受 config 中 debug 开关控制 |
| **🎨 仪式感** | `startup()` / `shutdown_panel()` / `print_logo()` | 启动/关闭时的品牌展示 |

实现位于 `packages/fp-terminal/src/fp_cli/display.py`，所有函数最终调用底层 `_styled_write(style, text)`。

## LLMStreamer

`class LLMStreamer` 负责逐块接收 LLM 输出并渲染到终端。

```
class LLMStreamer:
    def think(self, text: str):     # 渲染思考片段
    def write(self, text: str):     # 渲染输出片段
    def end(self, interrupted=False): # 结束流（interrupted=True 表示被中断）
```

- 每次 `think()` / `write()` 调用立即刷新到 stdout。
- `end()` 负责清理尾部状态（如关闭 spinner、输出换行）。
- 中断模式下保留已输出内容，仅标记终止。

---

## Spinner

`class Spinner` 提供后台旋转动画，用于耗时操作的视觉反馈。

```
class Spinner:
    def start(self):   # 启动动画线程
    def stop(self):    # 停止并清理
```

- 动画帧序列从 `~/.config/fp/config.json` 的 `display_styles.spinner_frames` 读取。
- 所有终端输出前自动暂停 spinner，输出后恢复。

## 问答块渲染（ask v2）

`CLIIO.ask()`（`cli_io.py`）在终端渲染结构化问题块并解析输入：

```
❓ <问题>
   1. <选项A>
   2. <选项B> （推荐）
   💡 推荐默认值：n（直接回车采纳）
❯ 
```

解析规则（展示层负责，返回的已是最终文本）：
- **空回车** → 采纳 `suggest`（无 suggest → 空串 = 未回答，不伪造）
- **编号 1..N** → 对应选项原文；越界编号按自由文本原样返回
- **其他** → 自由文本原样；EOF/Ctrl+C → 空串

**显示时序（防挤占回答区）**：`tool_call`/`tool_result` 展示是
`create_task` 异步调度（含逐段 0.02s 流式延迟），会插进问题块与输入
光标之间。`ask()` 两段防护：① 渲染前 `asyncio.wait` 已入队的展示任务
（工具参数行先落盘）；② 持 `LLMStreamer._get_tool_lock()` 渲染问题块并
读输入 —— 问答挂起期间新到的工具行在锁外排队，答完按序打印。

测试：`packages/fp-terminal/tests/test_cli_ask.py`（含 2 个时序回归用例）。

## 配置驱动样式

所有颜色/标记/截断长度均不硬编码：

```json
{
  "display_styles": {
    "info":     { "color": "cyan", "prefix": "ℹ" },
    "error":    { "color": "red",  "prefix": "✗" },
    "thought":  { "color": "green", "prefix": "◆" },
    "spinner_frames": ["⠋","⠙","⠹","⠸","⠼","⠴","⠦","⠧","⠇","⠏"]
  },
  "display_truncation": {
    "tool_output_max_len": 2000,
    "thought_max_len": 500
  }
}
```

代码中通过 `get_style(key)` 和 `get_truncation(key)` 访问。

## 斜杠补全（输入侧）

交互入口在 `packages/fp-terminal/src/fp_cli/main.py` 的 `SlashCompleter`：
输入 `/` 前缀时，从 `fp_core.commands.get_all_commands()` 取命令词条（含描述）做 Tab 补全。

- **惰性重载**：`get_completions` 每次调用前重新 `_load_words()`。
  原因：命令词表可能滞后于命令注册的变化（历史上的 `/reload` 是同进程原地重建、
  **不重建 `InputHandler`**；现已是进程级 execve 重启，但同进程的插件热启停与
  WebUI REST 重载仍会让缓存词表过期）。惰性刷新让命令变化**立即可补全**，
  注销后也立即消失。
- 仅当输入以 `/` 开头时才触发补全。

## 无头驻留模式（--headless）

`fp_cli/main.py` 的 headless 分支**不构造 `InputHandler`**：prompt_toolkit 的提示符、
输入历史、Tab 补全（含上一节的 `SlashCompleter`）全部不启用，logo 也不打印，
只留一行驻留提示（含 session id）。

- **退出条件只有信号**：交互模式 `input()` 读到 EOF（后台无 pty 启动）即 break 退出，
  实例当场死亡、zeta 名片失效；headless 把「没有输入」视为常态，stdin 是否可读、
  是否已 EOF 都不影响存活，`SIGINT`/`SIGTERM` 才收尾——与 REPL 走同一套
  `ctl.close()` → 统计面板 → 保存会话。
- **输出改行缓冲**：stdout/stderr 重定向到文件时默认块缓冲，驻留进程的日志会攒到
  退出才落盘（而它恰恰到收到信号才退出，等于永远看不到）。启动时对带
  `reconfigure` 的流开 line buffering，让日志实时可见。
- **续接照常消费**：热重启 handoff 仍由 `take_reload()` 取走并执行，
  区别只是完成后落入驻留循环，而非 REPL 输入提示。

## 热重启续接渲染（三入口）

工具面（`reload` 携口令）与命令面（`/reload`，人触发免口令）共用激活核心
`handoff.perform_exec_reload`，落盘 handoff `{sid, ts, frontend, kind}` 后
execve 重启。新实例三入口统一消费 `consume_reload_handoff` 并按 kind 分流：

- **kind=tool**：`state._pending_continue` 置位 → `continue_conversation(io=本入口IO)`
  → 渲染 Response → 置回 `None`；
- **kind=command**：`state._reload_notice` 置位 → 入口显示一行「🔄 热重启完成，
  会话 xxx 已恢复」→ 置回 `None`，回到正常输入（无挂起工具轮，不进续接）。

| 入口 | 续接与渲染方式 |
|------|----------------|
| **fp-terminal** | REPL 外层消费续接，经既有输出通道渲染 |
| **fp-webui** | lifespan 续接；事件进 EventBus 环形缓冲，客户端凭 `run_id` resync；并发由 `is_running` 拦截 |
| **fp-acp** | session/prompt 挂起的 req id 记 `FP_ACP_PENDING_REQ`，续接后补发 chunk + result |
