# 测试

FP 的自动化测试体系，覆盖引擎核心、插件系统与文档防漂移机制。

---

## 定位与策略

测试**不依赖真实 LLM**（mock `_invoke_llm` / `LLMResult` 预设返回），并**隔离文件 I/O**
（临时目录覆盖会话/配置路径），因此可离线、快速、重复运行。

| 原则 | 说明 |
|------|------|
| 🚫 不调真实 LLM | 所有 LLM 交互通过 fixture mock，测的是引擎逻辑而非模型行为 |
| 🧪 隔离文件 I/O | 会话目录、配置缓存全部指向临时目录，**任何测试都不写真实用户数据** |
| 🔍 防文档漂移 | `test_docs_consistency.py` 把源码当权威，校验文档中的数字声明 |
| 🛡 防门禁腐烂 | `test_check_docs_sync_cli.py` 在临时 git 仓库中验证文档同步脚本行为 |
| 🧱 隔离接口面 | 前端对 fp-core 只经 `fp_core.api`，导入白名单由 `test_api_surface.py` 强制（唯一接口组协议 §5） |

## 准备

测试依赖**不进各包 pyproject**（只在本文件登记），首次跑测试前一次性装齐：

```bash
pip install pytest pytest-asyncio httpx pyyaml textual rich wcwidth fastapi uvicorn websockets
```

- `pytest` 是唯一的纯测试依赖（只用到 `fixture` / `mark` / `raises`，`pytest>=7` 即可）
- `pytest-asyncio` 是 async 用例的执行引擎（缺了它 215 个 async 用例会以
  "async def functions are not natively supported" 全部失败——CI 曾因此爆炸）
- 其余都是各包的**运行时依赖**（httpx/pyyaml→fp-core、textual/rich/wcwidth→fp-terminal、
  fastapi/uvicorn/websockets→fp-webui），`pip install -e` 装包时会自然带入
- CI 的 `test` 任务按同一清单安装，且是 **os 矩阵**：ubuntu-latest × Python {3.11, 3.12, 3.13,
  3.14} + macos-latest × Python 3.12（macOS 只跑一版，职责是捕「平台差异」而非「版本差异」），
  与各包 classifiers 声明的支持面一致
- Windows 分两个 job：`test-windows` 全量 pytest 但 `continue-on-error`（**非阻断**，
  采集跨平台失败清单，待 Windows 移植完成后转硬门禁）；`onboarding-windows` 以窄口径
  （`test_setup` / `test_main_argv` / `test_config` / `test_appearance`）**阻断**，
  实证首跑向导与跨平台路径
- 跨平台 job（macOS / Windows）的 pytest 步骤把失败用例发布为 GitHub **annotations**
  （日志里打 `::error::`，见 `.github/workflows/ci.yml`）：Actions 日志需鉴权、无法匿名读，
  而 annotation 可经 `/repos/{owner}/{repo}/check-runs/{id}/annotations` **匿名读取**——
  在无真机、无 token 的环境里，这是自取非本机平台失败清单的通路（#169/#170 triage）

**全新机器环境自洽**（CI runner / 无开发机配置的环境）：根 `conftest.py` 与各包
tests/conftest.py 在引导期 `setdefault` 兜底 LLM 三键与 git 身份，缺了它们 87 个用例连环挂：

| 变量 | 兜底原因 |
|------|----------|
| `LLM_API_KEY` / `LLM_API_BASE_URL` / `LLM_MODEL` | 产品侧已**零默认**（三键无内置兜底，缺失即硬拒启动），测试须在 import 前 setdefault 齐三键；`fp_core.config` 在 **import 时**把它们焊成模块级常量（JSON > env > `""`）；runner 无 `~/.config/fp/config.json` → 恒为空 → `Agent` 构造被 `check_llm_config()` 拒绝（70 挂）。测试文件顶部的 `setdefault` 救不了——config 已被更早收集的模块 import |
| `GIT_AUTHOR_*` / `GIT_COMMITTER_*` | `fp ext` 的 new/remove/promote 自动 git commit，无 `user.name/email` 的机器报「作者身份未知」（17 挂） |

均为 `setdefault`：开发者本机的真实 config.json / git 身份优先，只在真空环境兜底。

### 隔离用户目录：patch 路径来源函数，别只依赖 XDG 环境变量

测试隔离「用户配置/数据目录」时，**不要只设 `XDG_CONFIG_HOME` / `XDG_DATA_HOME`**——
它们只在 Linux 生效；macOS（`~/Library/Application Support`）与 Windows（`%APPDATA%` /
`%LOCALAPPDATA%`）的 `platform_utils.get_config_dir()/get_data_dir()` 都不读这两个变量。
在 macOS 上只设 env，测试会悄悄读到**真实用户目录**，制造只在 macOS 复现的失败（#169：
`test_ext` 10 个 + `test_style` 4 个）。正确做法二选一：

- **patch 路径来源函数本身**：`patch("fp_core.platform_utils.get_config_dir", lambda: tmp)`——
  调用方（如 `fp_cli/style.py`）在**函数内** `from ... import get_config_dir`，补丁在调用点命中；
- **让被测代码经模块属性调用**该函数（写 `platform_utils.get_data_dir()`，而非
  `from ... import get_data_dir` 的本地绑定），使单一 monkeypatch 点生效
  （`ext_assets.py` 已按此改造，见 `docs/dev/资产分发系统.md`）。

## 运行

```bash
python -m pytest -q                 # 仓库根全量（根 pyproject 已登记各包 pythonpath，自洽）
python -m pytest packages/fp-core/tests -q   # 仅核心包
```

全量约 60 秒，输出 `994 passed, 2 skipped`。

> 当前覆盖 **60 个测试文件 / 996 个用例（994 通过 + 2 跳过）**，
> 横跨 fp-core / fp / fp-terminal / fp-acp 四包（根目录 `python -m pytest` 即可全量自洽，
> 不依赖 editable 安装指向）。
> **环境提示**：`test_setup` / `test_tui` 的交互性判定会读 `FP_IS_SUBAGENT` /
> `FP_SUBAGENT_ROLE`；在 subagent 子进程里跑全量会多出若干「假失败」，干净 shell 才是真值。
> `test_no_ghost_components_in_docs` 曾把用户级扩展命令 `/model`（fp-ext 分发，见 `EXT_CMDS` 白名单）误报为幽灵组件，现已修复。

## 会话隔离（重点）

`tests/conftest.py` 提供四个 **autouse** fixture，对所有测试默认生效：

```python
@pytest.fixture(autouse=True)
def _restore_llm_constants_after_each(): ...  # 还原 config 模块级 LLM_* 出厂常量

@pytest.fixture(autouse=True)
def _reset_config_cache(): ...        # 重置 config 模块 JSON 缓存

@pytest.fixture(autouse=True)
def _isolate_sessions_dir(tmp_path):  # 把 SESSIONS_DIR 指向 tmp_path

@pytest.fixture(autouse=True)
def _isolate_data_dir(tmp_path):      # 把 config._FP_DATA_DIR 指向 tmp_path（隔离三来源资产）
```

**LLM_* 常量还原**：`config.set_active_llm_state()`（/model 热切换入口）用
`globals()` 写 `LLM_ACTIVE_ID / LLM_MODEL / LLM_API_KEY / LLM_EXTRA_BODY` 等
模块常量。若测试调用过它（如 `test_llm_providers`），常量会被污染成"上次激活项"，
殃及同进程后续测试。conftest 在 import 时对九个 `LLM_*` 常量做出厂快照，
每个测试后还原（未定义项删除而非 setattr）。与 `_reset_config_cache` 互补：
后者管 `_json_cfg` 文件缓存，本 fixture 管内存激活态。

**背景**：`Agent.__init__` 无条件创建 `SessionManager` 并写入
`config.SESSIONS_DIR`（`~/.local/share/fp/sessions/`）。早期 `test_agent_tool_parallel.py`
未隔离该目录，导致全量测试在真实会话目录中产生多个测试垃圾会话
（内容形如 `sleep_1/sleep_2`、`test lifecycle`），污染用户会话记录。

**修复**：`_isolate_sessions_dir` 同时 patch 两个引用点：
- `fp_core.config.SESSIONS_DIR`（`agent.py` 中 `os.makedirs` 用的）
- `fp_core.core.session.SESSIONS_DIR`（`SessionManager` 内部用的）

> **新增测试无需额外配置即继承隔离**。若某测试确实需要操作真实会话路径，
> 应在测试内显式 patch，而不是取消全局隔离。

## 文档同步门禁（scripts/check_docs_sync.py）

pre-commit 钩子：**代码变更 → 关联文档跟进提醒**（基于 git diff 变更流，非文本比对）。

- 内容修改（M）→ 只要求「行为描述类」文档（`docs/dev/…`）确认
- 结构变更（增/删/改名）→ 额外要求「清单类」文档（README / guide 参考）确认
- 测试文件（`packages/fp-core/tests/*.py`）变更 → 要求 `docs/dev/测试.md` 确认；
  CI 工作流（`.github/workflows/*.yml`）变更同样落到 `docs/dev/测试.md`（矩阵/平台覆盖在彼处登记）
- 首跑配置入口（`packages/fp/src/fp/setup.py`）变更 → 要求 `docs/dev/项目概览.md` 确认
- **反向关联（DOC_LINKS，文档 → 代码）**：文档变更时，其登记的关联代码文件
  本次未同步变更 → 输出提醒（**不阻断**，文档允许先行）；`--audit` 会校验
  关联代码文件仍存在（防文档里「源码真相」引用因重构/改名断裂）。
  登记原则：只登记「文档内容明确指向实现」的文档（self 操作指南、dev 行为文档），
  不为纯清单/索引类（README）登记。

```bash
python scripts/check_docs_sync.py                 # pre-commit：检查暂存区
python scripts/check_docs_sync.py --since HEAD~3  # 主动触发
python scripts/check_docs_sync.py --audit         # 审计规则盲区 + 文档关联断裂
```

行为由 `test_check_docs_sync_cli.py` 在临时 git 仓库中逐场景验证。

## pre-commit 门禁脚本清单

`.pre-commit-config.yaml` 登记五个 local 钩子（`repo: local` + `language: system`，
避免 GitHub 网络依赖）：

| 钩子 | 脚本 | 职责 | 显式放行 |
|------|------|------|----------|
| `ruff-check` | ruff | 静态检查（`--fix --exit-non-zero-on-fix`） | — |
| `ruff-format` | ruff | 代码格式化 | — |
| `docs-sync` | `scripts/check_docs_sync.py` | 代码改动 → 关联文档同步（见上节） | `FP_DOCS_SYNC_ALLOW=1 git commit` |
| `dep-layers` | `scripts/check_dep_layers.py` | 四层依赖模型（L0–L4，见 `docs/self/README.md` §3）静态检查：内核 import 扩展（L1→L2）、L2 跨单元互依 → ERROR 阻断；入口分发 / 动态加载 → WARN 不阻断 | 无（ERROR 即真违规，修代码而非绕钩子） |
| `charter-guard` | `scripts/check_charter.py` | 宪章哈希锚点守卫（`docs/CHARTER.md` 不得被静默修改，宪章第 0 条） | `FP_CHARTER_ALLOW=1 git commit -m "charter:amend — <理由>"` |

> **环境注意**：`language: system` 钩子直接调用 PATH 上的 `ruff` / `python`，
> 需与 venv 的 Python 版本匹配。本机曾因 py3.12 → 3.14 迁移导致 `pre_commit`
> 模块在钩子解释器下缺失，需以对应 venv 重新 `pre-commit install`。

## 接口面门禁测试（test_api_surface.py / test_wake.py）

唯一接口组（Portal，见 `docs/dev/唯一接口组协议.md`）落地后，测试套件新增两个门禁测试：

- **`test_api_surface.py` —— 隔离边界的红绿灯**（协议 §5）：
  扫描 fp-terminal / fp-webui / fp-acp / fp 四前端源码，凡 `import fp_core...`
  不在白名单（`fp_core.api` + 纯工具 `logger/config/platform_utils`）即失败；
  并反向约束 core 不得依赖任何前端包（分层方向固定 core ← 前端）。
  除导入面外另覆盖 api 行为：两域判据（`run.*` 无实例 → `InstanceNotOpenError`、
  `ctl` 生命周期幂等）、`ExitReason` 映射、`take_reload` 空 handoff、会话用例、
  事件目录冻结。
- **`test_wake.py` —— 唤醒链路**：空闲泵消费 wake 级注入（邻居铃声、后台任务终态）——
  jobs 层 wake 标记与 drain、注入身份协议（非人类 `⁂[kind]` 标头 / `human=True`
  裸文本 / `is_injected` 判定）、`Agent.process_wakeup` 不进用户输入只消费注入、
  `portal.run.wake`（空闲消费 / 忙碌保留 / 未开启 None，人类优先）、空闲泵自动唤醒，
  以及空闲泵对空闲完成的后台任务自动起轮报告。

这两个测试是「重构不逃逸」的机器保证：前端一旦绕过 api 触碰内部，或唤醒路径回归，
本地全量与 pre-commit 前的测试即红。
