# 唯一接口组协议（Portal Protocol）

> 目标：**外界（terminal / acp / webui 及未来任何前端）与核心实例的一切交流，
> 只经由唯一一个可扩展的接口组 `fp_core.api`**。
> 接口组内部严格二分：**实例内的操作（run）** 与 **控制实例的操作（ctl）**。

---

## 0. 设计原则

1. **单一通信面**：前端对 fp-core 的实例通信 import 面 = `fp_core.api` 一个模块。
   纯工具模块（`fp_core.logger` / `fp_core.config` / `fp_core.platform_utils`）
   不参与实例通信，列入白名单；除此之外的 fp_core 导入一律违规（有测试强制）。
2. **两域分离**：
   - `portal.run.*` — **实例内的操作**：实例已存在，作用于其内部运行
     （发消息、续接、打断、斜杠命令、ask 应答、读状态/转写）。
   - `portal.ctl.*` — **控制实例的操作**：作用于实例本身的生杀与配置
     （开启、关闭、热重启、会话管理、钩子/插件注册）。
   - 判据：**该操作在实例不存在时是否还有意义**。有意义 → ctl；必须先有实例 → run。
3. **数据越界只走协议对象**：前端不得触碰 `state.*`、`conversation.*`、
   `session.*` 内部；跨边界只传 `Response` / `InstanceStatus` / `Event` /
   `ReloadDirective` / `ExitReason` 等协议数据结构。
4. **样板归核**：会话重建、reload 续接消费、prompt 注入重放等曾由前端手写的
   多步序列，全部收编为核心用例 API，前端只调一次。
5. **可扩展**：接口组以 Protocol 定义、可注册扩展（hooks/plugins/事件订阅）；
   新增操作只做加法，不破坏既有前端。

## 1. 唯一入口

```python
from fp_core.api import portal          # 进程级单例，唯一入口对象

class Portal(Protocol):
    ctl: ControlPlane                   # 控制实例的操作
    run: RunPlane                       # 实例内的操作
    def subscribe(self, handler: EventHandler) -> Subscription
        # 出向事件流的唯一订阅点（详见 §4）
```

前端生命周期（所有前端统一为这四步）：

```python
portal.ctl.bootstrap()                  # 入口第一行：捕获启动命令（原 capture_launch_command）
portal.ctl.open(...)                    # 创建实例（原 Agent(...) + ensure_initialized）
...  portal.run.* / portal.ctl.sessions.* / portal.subscribe(...) ...
await portal.ctl.close(reason=...)      # 终结（原 agent.shutdown + 标志位语义）
```

## 2. 实例内的操作 — `portal.run`

前置条件：`portal.ctl.open()` 已完成。**实例不存在时调用 → `InstanceNotOpenError`。**

```python
class RunPlane(Protocol):
    # ── 对话流 ──
    async def send(self, text: str, io: IOChannel | None = None) -> Response
        # 原 agent.process；io=本次交互的输出通道（前端各自实现 IOChannel）
    async def continue_(self, io: IOChannel | None = None) -> Response
        # 原 agent.continue_conversation；仅供 reload 续接（配合 ctl.take_reload）
    def cancel(self) -> None
        # 原 agent.cancel —— 用户打断

    # ── 斜杠命令 ──
    async def command(self, line: str) -> tuple[bool, str]
        # 原 agent.handle_command
    @property
    def commands(self) -> dict[str, str]
        # 原 agent.commands / get_all_commands —— 前端补全与 ACP 命令注册用

    # ── ask 应答（带内回执） ──
    def reply(self, text: str, ask_id: str | None = None) -> bool
        # 原 WebSocketIO.feed_reply 上提：任何前端的 ask 应答都走这里

    # ── 只读状态（替代全部 state.* 触碰） ──
    @property
    def status(self) -> InstanceStatus
        # dataclass: model / session_id / is_processing / cancelled / frontend
    @property
    def transcript(self) -> list[dict[str, Any]]
        # 当前会话消息只读快照（原 state.conversation.messages）
    def reset_cancelled(self) -> None
        # 原 agent.reset_cancelled

    # ── 唤醒（空闲泵消费 wake 级注入：如邻居铃声） ──
    async def wake(self, io: IOChannel | None = None) -> Response | None
        # 实例空闲且有 wake 级待注入事件（jobs.has_pending_wake()）时起一轮消费它；
        # 忙碌或无待处理 → None（不打断，人类优先）。
        # portal 内部空闲泵（ctl.open 时启、ctl.close 时停）与下游主动唤醒均调用本入口。
```

**`IOChannel` 归属**：协议定义由 `fp_core.api` 导出，**前端实现自己的通道**
（CLIIO → terminal、ACPIO → acp）；`WebSocketIO` / `RestIO` 保留在 core ——
其曾有的分层倒挂（EventBus 定义在 fp-webui、core 用 Any 兜底）已由 EventBus
下沉 core 根治，通道现以强类型 `EventBus` 引用。前端经 api 导入它们。

## 3. 控制实例的操作 — `portal.ctl`

实例不存在时也可调用（open/bootstrap/close 本来就是对"不存在的实例"操作）。

```python
class ControlPlane(Protocol):
    # ── 生命周期 ──
    def bootstrap(self) -> None
        # 入口第一行调用：捕获启动命令（原 handoff.capture_launch_command）
    async def open(self, *, resume: str | None = None,
                   plugins: Sequence[Plugin] = (),
                   io: IOChannel | None = None) -> None
        # 创建实例并完成初始化（原 Agent(...) + 注册插件 + ensure_initialized 一体）
    async def close(self, *, reason: ExitReason = ExitReason.FINAL) -> None
        # 关闭实例。reason 消解原 silent_shutdown/nuclear_exit 布尔散落：
        #   FINAL   —— 正常终结：保存上下文 + 摘要 + 退出提示
        #   RECYCLE —— 热切换：保存上下文，静默（reload / webui 重建用）
        #   DISCARD —— 不留痕：删除当前会话文件，静默（原 nuclear_exit / acp 退出）

    # ── 热重启协议（原 handoff 前端消费样板收编） ──
    def take_reload(self) -> ReloadDirective
        # 消费 FP_RELOAD_HANDOFF，内部完成 _reload_notice/_pending_continue 的
        # 置位与清空；前端只读结构化结果，永不触碰 state 私有字段：
        #   ReloadDirective(notice: str | None, should_continue: bool)
        # 前端标准用法：
        #   d = portal.ctl.take_reload()
        #   if d.notice: 前端渲染(d.notice)
        #   if d.should_continue: resp = await portal.run.continue_(io=...)

    # ── 会话管理（原 8 处手写重建样板收编） ──
    @property
    def sessions(self) -> SessionCtl: ...
    class SessionCtl(Protocol):
        def new(self) -> SessionInfo           # 原 webui/acp 手写 fork+rebuild（同 commands/new.py 语义）
        def load(self, sid: str) -> SessionInfo | None  # 目标不存在 → None（前端决定 404/自动新建）
        def clear(self) -> None                # 清空当前会话并重建（同 commands/clear.py 语义）
        def list(self) -> dict[str, SessionMeta]        # {sid: meta}，同 SessionManager.list_sessions()
        def delete(self, sid: str) -> bool
        def update_meta(self, sid: str | None = None, **kw) -> None
        def path(self, sid: str) -> str        # 供 webui 只读文件端点（原 _session_mod._session_path 私用）
        def read_messages(self, sid: str) -> list[dict[str, Any]] | None   # 只读解析；文件不存在 → None
        # new/load 内部统一实现：rebuild system prompt → 应用插件注入（prompt append 重放）
        #                      → reset → load_context → set_messages
        # —— webui 的 _reapply_prompt_append 补丁上移归核，acp 丢 system prompt bug 同时修复

    # ── 扩展点（接口组的"可扩展"部分） ──
    @property
    def hooks(self) -> HookCtl:
        def register(hook: LifecycleHook, fn, *, name: str, priority: int = 100) -> None
        def unregister(hook: LifecycleHook, name: str) -> bool
        # 原 acp/webui 直接拿 agent.lifecycle 的收编面；HookContext/LifecycleHook 由 api 导出
    @property
    def plugins(self) -> PluginCtl:
        def register(plugin) -> None
        def unregister(name: str) -> bool
        # open(plugins=[...]) 为推荐路径（保证在初始化前注册）；此二者供运行期增删
```

### `ExitReason`（替代布尔标志位）

| reason | 保存上下文 | 摘要 | 删除会话 | 前端提示 |
|---|---|---|---|---|
| `FINAL` | ✅ | ✅ | ❌ | 显示退出提示 |
| `RECYCLE` | ✅ | ✅ | ❌ | 静默 |
| `DISCARD` | ❌ | ❌ | ✅ | 静默 |

## 4. 出向事件流 — `portal.subscribe`

**唯一出向通知通道**（与 run 的点对点流式输出互补分工）：

- **事件流**：跨轮次、生命周期级的通知（llm_start/llm_end、tool_call、
  tool_result、error、shutdown、reload_done、done、cancelled、say…）。
  **归 core 所有**（`EventBus` 从 fp-webui 下沉到 `fp_core.core.events`，
  经 `fp_core.api` 导出；保留 seq/run_id 断连续传语义），core 内置 lifecycle→event 转发，
  前端不再各自写桥接插件。
- **IOChannel**：轮内、点对点的流式渲染（stream_think/stream_write）+ ask 交互。
  实现归前端，经 `run.send(..., io=)` 绑定本次交互。

```python
def subscribe(self, handler: Callable[[Event], Awaitable[None]]) -> Subscription
    # Event: TypedDict/dataclass — type: str, seq: int, **payload
    # 事件 type 目录冻结为协议常量（EVENT_TYPES），新增只做加法
```

分工判据：**core 内部发生了什么 → 事件流；core 要把这一轮的输出画出来 → IOChannel。**

## 7. 兼容与非目标

- **不动**：`Agent`/`State`/命令层/插件系统的内部实现——portal 是**包装**，
  不是重写；既有 core 测试继续直接测内部。
- **不动**：webui 前端 JS 事件协议（type 目录冻结兼容）。
- **不做**：多实例（一进程一 portal，语义与现状一致）。
