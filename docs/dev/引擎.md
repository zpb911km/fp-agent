## Agent 类 (`packages/fp-core/src/fp_core/core/agent.py`)

`Agent` 是整个系统的编排层，持有所有服务实例，管理主循环。它不直接持有上下文状态——`ConversationState` 是唯一的事实源。

当前源代码约 **762 行**。

### 类签名

```python

    def __init__(
        self,
        enable_log: bool = False,
        resume: str | None = None,
        io: IOChannel | None = None,
        tool_executor: ToolExecutor | None = None,
        prompt_builder: PromptBuilder | None = None,
    )
```

**参数**：

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `enable_log` | bool | `False` | 是否输出调试日志 |
| `resume` | str \| None | `None` | 会话恢复模式：`None`/`False`=新会话，`True`/`"auto"`=续最近，`"s_xxx"`=指定会话 |
| `io` | IOChannel \| None | `None` | IO 通道（默认使用 CLI） |

### 核心方法

```python
async def process(self, user_input: str, io: IOChannel | None = None) -> Response
```

处理一条用户输入。返回值 `Response` 包含最终回复内容。内部执行完整的 LLM 调用循环（见架构设计中的数据流图）。

入口区钩子链（边 #2–#11，见插件系统 §6.2）：`ON_INITIALIZED`（幂等检查）→ 空输入发 `ON_EMPTY` 早退 → `ON_INPUT` → 命令路径 `ON_BEFORE_COMMAND`（blocked 可阻断）→ `ON_COMMAND`（post，含 output/latency_ms，**唯一命令观察点**）→ 未处理发 `ON_FALLTHROUGH`；非命令路径发 `ON_MSG_ENTER` → 过滤被拦发 `ON_MESSAGE_BLOCKED(source=filter)` → 最终裁定被拦发 `ON_MESSAGE_BLOCKED(source=received)` → 入库后发 `ON_CTX_APPEND(op=user)`。

循环区钩子链（边 #13–#29，块3）：环顶中断抛出前发 `ON_INTERRUPT` → repair_tool_ordering 实际修复时发 `ON_CTX_REPAIR`（静默 mutation 观察点）→ `ON_BEFORE_LLM_CALL`（cancelled 可取消，早退发 `ON_EARLY_EXIT`）→ `ON_AFTER_LLM_CALL`（**含 usage/model/latency_ms 逐调用统计字段**）→ 守卫分支三选一互斥：`ON_TOOL_BLOCKED`（block_tool_execution）/ `ON_STREAM_STRIP`（流式中断剥离 tool_calls）/ `ON_LLM_PASS`（正常通过）→ 入库后发 `ON_CTX_APPEND(op=assistant)` → break 分支：`ON_STREAM_INTERRUPT`（中断）或 `ON_TURN_END`（正常终答）。异常路径：`ON_ERROR`（handled 可恢复环顶）→ 重试链 `ON_LLM_RETRY` → 成功 `ON_LLM_RETRY_OK` / 失败 `ON_LLM_FATAL(stage=retry_failed)`，非 tool 错误直发 `ON_LLM_FATAL(stage=unrecoverable)`；中断直抛 `ON_CANCEL`。

工具子机钩子链（边 #30–#44，块4）：`ON_TOOL_SELECT`（cancelled 拦截后**为每个 tool_call 补写占位结果**再发 `ON_TOOL_CANCELLED`，消除悬挂 tool_calls；modified_tools 过滤）→ 每工具：`ON_TOOL_CALL`（拒绝 → `ON_TOOL_REJECTED`；改参 → `ON_TOOL_EXEC` 观察定稿参数）→ `ON_TOOL_ERROR` 分支二选一：`ON_TOOL_SUPPRESSED`（抑制）/ `ON_TOOL_ERROR_PROPAGATED`（传播）→ **`_result_gate` 统一 RESULT 门**（拒绝/抑制/成功三路均过，缺陷①修复）：`ON_TOOL_RESULT` → blocked/modified 消费后发 `ON_RESULT_MUTATED` → gather 返回先发 `ON_TOOL_RESULTS_READY` → 逐条入库走 `_append_tool_message`（每条发 `ON_CTX_APPEND(op=tool)`）→ 中断元素补记剩余后发 `ON_TOOL_PARTIAL`，gather 整体取消全量补记后发 `ON_TOOL_ABORT` → 本轮完成发 `ON_ITERATION` 回环顶。

`io` 参数：可选的 IO 通道覆盖。WebUI 模式传入 `WebSocketIO`，REST 模式传入 `RestIO`。通过 `contextvars` 绑定到当前 asyncio Task，详见下方 IOChannel 体系说明。


## IOChannel 体系

IO 通道抽象层用于解耦 CLI / WebUI / REST 的输入输出，使命令和 Agent 内部方法不直接依赖 `input()` 或 `display` 模块。

### 类层级

```
IOChannel（抽象基类）
 ├── CLIIO          — 终端交互，使用 input() + display 模块
 ├── WebSocketIO   — WebSocket 通道，通过 EventBus 推送输出，支持双向交互
 └── RestIO         — 静默通道，ask() 返回空字符串（单次请求-响应模式）
```

### contextvars 绑定机制

`io` 参数不再以实例变量方式存储，而是通过 `contextvars.ContextVar` 绑定到当前 asyncio Task：

- `_current_io.set(io)` 在 `process()` / `continue_conversation()` 入口调用 → 绑定到当前 asyncio Task
- `_current_io.reset(token)` 在 `finally` 块中恢复 → 保证不泄漏
- `agent.io` 属性优先返回 context var 覆盖值，无覆盖时 fallback 到 `__init__` 注入的默认通道
- 同入口同步绑定 `current_state`（`core/state.py` 的 `ContextVar`）：工具契约 `execute(params)` 不携带上下文，需要活体 State 的工具在执行期经 `get_current_state()` 导线读取，`finally` 一并恢复
- 同样**不自动传播到子 Task**，子 Task 需经 `Agent.make_io_context()` 手动传播

这样设计的目的是**防并发竞态**：当多个协程并发访问同一个 Agent 实例时，每个协程通过 contextvars 获得自己绑定的 IO 通道，互不干扰。

⚠️ **跨 Task 隔离**：`contextvars` 绑定到创建它的 Task，不会自动传播到子 Task。如果子 Task 需要访问正确的 IO 通道，必须使用 `Agent.make_io_context()` 手动传播。

### 各通道特点

| 通道 | ask() | say/info/error | 适用场景 |
|------|-------|----------------|----------|
| **CLIIO** | `run_in_executor(input())` | 终端着色输出 | CLI 终端 |
| **WebSocketIO** | 发 ask 事件 + Future 等待 | EventBus 推送 | WebUI / ACP |
| **RestIO** | 返回 `""`（静默取消） | 空操作 | REST API |

## Response 对象

```python
@dataclass
class Response:
    content: str = ""
    metadata: dict = field(default_factory=dict)
    error: str | None = None
```

| 字段 | 类型 | 说明 |
|------|------|------|
| `content` | str | 最终回复文本（纯文本，非 Markdown） |
| `metadata` | dict | 元数据（当前未使用，预留） |
| `error` | str \| None | 错误信息。非 `None` 时表示处理过程中发生了异常 |

**使用示例**：

```python
agent = Agent(resume="auto")
response = await agent.process("Hello!")
if response.error:
    print(f"Error: {response.error}")
else:
    print(response.content)
```

## LifecycleManager (`packages/fp-core/src/fp_core/core/lifecycle.py`)

事件驱动的生命周期管理器，支持同步/异步钩子，按优先级执行。

### 核心方法

```python

    self,
    hook: LifecycleHook,
    func: Callable,
    priority: int = 100,
```

注册钩子函数。

| 参数 | 类型 | 默认值 | 说明 |

| `hook` | LifecycleHook | — | 要注册的钩子枚举 |
| `func` | Callable | — | 钩子处理函数（同步或异步均可） |
| `priority` | int | `100` | 优先级，越小越先执行 |
| `name` | str \| None | `None` | 名称（用于注销/调试），默认取函数名 |

```python

```

注销指定钩子。成功返回 `True`，未找到返回 `False`。

```python
async def emit(
    self,
    hook: LifecycleHook,
    context: HookContext | None = None,
    **kwargs,
) -> HookContext
```

异步触发钩子。返回最终的 `HookContext`（可能被钩子修改）。调用方应检查返回的 `context.data` 获取插件修改后的值。

**emit 调用约定**：

1. **kwargs → context.data 合并**：所有额外的 `**kwargs` 会自动合并到 `context.data` 中（若传入 `data=dict()` 会展开合并而非覆盖嵌套），钩子处理函数通过 `context.data[key]` 或 `**context.data` 解包访问。
2. **返回值合并**：若某个钩子函数返回了 `HookContext` 实例，`emit` 会用返回值替换当前 context，实现链式数据传递。
3. **异常策略（统一）**：任何钩子异常都会设置 `context.error` 并标记 `context.stop_propagation = True`，调用方自主检查 `context.error` 决定如何处理。
4. **停止传播**：通过 `context.stop_propagation = True` 可提前终止后续钩子执行，用于守卫拦截场景。

### @hook 装饰器

```python
from fp_core.core.lifecycle import LifecycleHook, LifecycleManager, hook

lifecycle = LifecycleManager()

@hook(lifecycle, LifecycleHook.ON_BEFORE_LLM_CALL, priority=50)
async def my_llm_guard(context, messages, tools, **kwargs):
    """在 LLM 调用前检查消息内容"""
    for msg in messages:
        if msg["role"] == "user" and len(msg["content"]) > 10000:
            context.data["cancelled"] = True
            context.data["cancel_reason"] = "消息过长"
    return context
```

**装饰器定义**（示意）：

```python
def hook(lifecycle: LifecycleManager, hook_enum: LifecycleHook, priority: int = 100, name: str | None = None):
    def decorator(func):
        lifecycle.register(hook_enum, func, priority=priority, name=name)
        return func
    return decorator
```

### 完整示例

```python
from fp_core.core.lifecycle import LifecycleManager, LifecycleHook, HookContext

lifecycle = LifecycleManager(enable_log=True)

# 示例：只打印、不修改的钩子
def on_message(ctx: HookContext, **kwargs):
    print(f"[Observe] 用户说了: {kwargs.get('filtered_content', '')[:50]}")

lifecycle.register(LifecycleHook.ON_MESSAGE_RECEIVED, on_message, priority=200)

# 示例：可修改数据的钩子
async def on_filter(ctx: HookContext, **kwargs):
    content = kwargs.get("filtered_content", "")
    if "敏感词" in content:
        ctx.data["blocked"] = True
        ctx.data["block_reason"] = "包含敏感内容"
    return ctx

lifecycle.register(LifecycleHook.ON_MESSAGE_FILTER, on_filter, priority=50)
```
