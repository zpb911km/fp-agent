# 会话模块

---

## SessionManager (`packages/fp-core/src/fp_core/core/session.py`)

会话管理器负责会话的持久化。它**不持有上下文消息**——只负责读写文件。上下文状态的所有权在 `ConversationState`。

### 类签名

```python
class SessionManager:
    def __init__(self, resume: str | None = None)
```

| 参数 | 类型 | 值 | 行为 |
|------|------|----|------|
| `resume` | `None` / `False` | — | 创建新会话（默认） |
| `resume` | `True` / `"auto"` | — | 续最近会话（按 `updated` 时间） |
| `resume` | `"s_xxx"` | — | 续指定会话 ID（如果存在） |

内部逻辑：先归一化 `resume` 值（`False`→`None`，`True`→`"auto"`），再按分支处理。

### 属性

```python
@property
def session_id(self) -> str
```

当前会话 ID，格式如 `s_260606_160000000000`。

### 会话管理方法

```python
def list_sessions(self) -> dict[str, dict[str, Any]]
```

扫描 `~/.local/share/fp/sessions/` 目录，返回所有会话的 meta 信息字典：`{sid: {meta_fields}}`。

```python
def switch_session(self, sid: str) -> bool
```

切换到指定会话。目标会话必须存在。返回是否成功。
切换成功时会同步进程级「当前会话」标识（见下节），使 `get_current_session_id()` 始终指向活动会话。

```python
def create_session(self) -> str
```

创建新会话并切换到它。返回新会话 ID。同样同步进程级「当前会话」标识。

```python
def resume_latest(self) -> bool
```

尝试续最近会话（按 `updated` 字段）。如果存在历史会话则切换到它并返回 `True`；否则创建新会话并返回 `False`。

```python
def delete_session(self, sid: str) -> bool
```

删除指定会话文件。不能删除当前会话。返回是否成功。

```python
def clear_session_file(self)
```

清空当前会话文件（重置为默认 meta，删除所有历史消息）。

### 消息读写方法

```python
def save_message(self, role: str, content: str, **kwargs)
```

追加一条消息到文件末尾。自动更新文件内嵌的 meta（`message_count++`, `updated`）。支持 `tool_calls`、`tool_call_id`、`reasoning_content` 等附加字段。

> **思考模型回传约定**：assistant 消息的 `reasoning_content` 会随会话持久化保留。
> 发送给 LLM 时由 `ConversationState.get_messages_for_llm(with_tools=...)` 决定去留——
> 带 `tools` 的请求回传历史思维链（DeepSeek v4 官方要求），不带 `tools` 则剥离省 token。
> 详见《LLM通信》「思考内容跨轮回传」。

```python
def save_context(self, context: list[dict[str, Any]])
```

将完整上下文**重写**到文件（原子写入：先写 `.tmp` 再 `os.replace`）。跳过第一条 `system` 消息（由 `load_context` 重新加载）。更新 `message_count` 和 `updated` 时间戳。

```python
def ensure_on_disk(self) -> bool
```

会话文件是**惰性创建**的：空会话（过滤 `system` 后为空）经 `save_context` 会静默跳过，且 `save_context` 的写失败也被其内部吞掉。`ensure_on_disk()` 在文件不存在时无条件写一行 meta 的占位文件（已存在则 no-op），保证新进程 resume 能通过 `os.path.exists` 校验恢复；返回值 = 文件是否真的在盘上。reload 激活核心（`core/handoff.perform_exec_reload`）落盘后据此做存在性硬校验——文件不在盘上绝不 exec 重启。

```python
def load_context(self, system_prompt: str) -> list[dict[str, Any]]
```

加载会话文件中的所有历史消息。返回的列表第 0 项是传入的 `system_prompt`（作为 `{"role": "system", "content": system_prompt}`），后续项是从文件读取的历史消息（跳过第 1 行的 meta）。

```python
def update_meta(self, sid: str | None = None, **kwargs)
```

更新指定会话的内嵌 meta 字段。自动更新 `updated` 时间戳。如果 `sid` 为 `None` 则更新当前会话。

### 会话文件路径（模块级公开函数）

```python
def session_file_path(sid: str) -> str
```

返回 `sid` 对应的 `.jsonl` 文件路径（`~/.local/share/fp/sessions/<sid>.jsonl`）。
原 `_session_path` 为私用实现，现由本函数公开，作为 `api.ctl.sessions.path` 的底层，
供 webui 只读文件端点等前端使用。

## 会话用例层与统一入口（`session_ops` / `ctl.sessions`）

会话管理分三层：**持久化底层** `SessionManager`（只读写文件，见上）、
**用例实现层** `core/session_ops.py`（组合底层完成「新建／切换／清空」等完整用例）、
**统一入口** `fp_core.api.portal.ctl.sessions`（`SessionCtl`，前端唯一调用面）。

`SessionCtl` 收编原 webui／acp／命令层 **8 处手写**「重建 system prompt + reset +
load_context + replace_all」样板，前端只调一次：

| 方法 | 语义 | 返回 |
|------|------|------|
| `new()` | 新建空白会话（落盘当前 → 分配新 sid → 重建上下文），同 `commands/new.py` | `SessionInfo` |
| `load(sid)` | 切换到历史会话 | `SessionInfo`；目标不存在 → `None`（前端决定 404 或自动新建） |
| `clear()` | 清空当前会话文件并重建，同 `commands/clear.py` | — |
| `list()` | 全部会话元数据 `{sid: meta}`，同 `SessionManager.list_sessions()` | `dict[str, SessionMeta]` |
| `delete(sid)` | 删除指定会话文件 | `bool` |
| `update_meta(sid=None, **kw)` | 更新会话 meta（`sid` 缺省 = 当前会话） | — |
| `path(sid)` | 会话文件路径（`session_file_path` 底层，见上） | `str` |
| `read_messages(sid)` | 只读解析会话消息（含 system）；文件不存在 → `None` | `list[dict]` |

`core/session_ops.py` 为上述用例的核心实现，导出 `fork_new` / `switch_to` / `clear` /
`read_messages` 与 `SessionInfo` / `SessionMeta`（后者经 `fp_core.api.types` 再导出，
依赖方向 `api → core`）：

- `fork_new(state)` — 落盘当前 → `create_session` → 重建 → `reset` → `clear_session_file`。
- `switch_to(state, sid)` — 落盘当前 → `switch_session` → 重建并加载目标上下文；
  目标不存在返回 `None`。
- `clear(state)` — 重建 → `reset` → `clear_session_file`。

> `switch_to` 以 `set_messages(prompt, saved)` 整体覆盖，修复原分散实现的两处缺陷：
> acp 用 `replace_all(saved)` 丢 system prompt（`saved` 不含 system 消息）；
> webui／acp 在目标为空会话时残留旧会话消息（空即清空）。

## 会话重建与 prompt 注入重放

`State.rebuild_system_prompt()` 重建 system prompt 后，会**重放**插件注入的
`prompt_appends`（`Agent.ensure_initialized` 在 `ON_INIT` 后捕获并缓存归一化结果），
保证插件 `system_prompt_append` 跨会话重建（`/clear` `/new` `/resume` 及上述
`ctl.sessions` 用例）不丢失。

- 原 webui 独有补丁 `_reapply_prompt_append` 上移归核，acp 侧丢 system prompt 的
  bug 一并修复。
- 初始注入与重建重放共用同一归一化规则：`prompts.normalize_prompt_append`
  （归一化 `str` / `list[str]`、过滤空白段、空行拼接），由 `apply_system_prompt_append`
  实际应用。

## 进程级当前会话（`get_current_session_id`）

```python
def get_current_session_id() -> str | None
```

返回**当前进程内活动会话**的 ID（模块级变量，非 ContextVar）。供插件给事件标注会话归属
（journal 落盘、subagent 父子关联等）—— 钩子 payload 里并非每条都带 `session_id`。

同步规则：`SessionManager.__init__`、`switch_session()`、`create_session()` 三处注册。
因此 `/resume` 等运行中切换会话后，该值立即指向新会话；切换失败（目标不存在）不改变原值。

## 会话文件格式

每个会话存储为 **一个 `.jsonl` 文件**，位于 `~/.local/share/fp/sessions/` 目录下。

### 文件结构

```json
// 第 1 行 — meta 信息（JSON 单行）
{"__meta__": true, "id": "s_260606_160000000000", "created": "2026-06-06 16:00:00", "updated": "2026-06-06 16:30:00", "summary": "用户问题概要", "message_count": 12}

// 第 2 行起 — 消息（按时间正序，最新在末尾）
{"role": "user", "content": "Hello"}
{"role": "assistant", "content": "Hi! How can I help?"}
{"role": "user", "content": "查询天气"}
{"role": "assistant", "content": "", "tool_calls": [{"id": "call_xxx", "type": "function", "function": {"name": "get_weather", "arguments": "{\"city\": \"北京\"}"}}]}
{"role": "tool", "content": "{\"temperature\": 25}", "tool_call_id": "call_xxx"}
{"role": "assistant", "content": "北京当前 25°C"}
```

### 格式约定

- **第 1 行** — 固定为 meta 行，包含 `__meta__: true` 标记
- **第 2+ 行** — 消息行，不含 `system`（system prompt 由 PromptBuilder 在加载时重新创建）
- **正序** — 最早的消息在前，最新消息在末尾
- **单文件** — 没有独立的 meta 文件或 `_current` 文件
- **system 不入文件** — 第一条 system 消息在 `save_context` 时被跳过

### meta 字段

| 字段 | 类型 | 说明 |
|------|------|------|
| `__meta__` | bool | 固定为 `true`，用于标识 meta 行 |
| `id` | str | 会话 ID |
| `created` | str | 创建时间 `"YYYY-MM-DD HH:mm:ss"` |
| `updated` | str | 最后更新时间 |
| `summary` | str | 会话摘要（取自最后一条用户消息的前 20 字符，`save_and_summarize` 统一入口生成，**非 LLM**——切换/新建/退出同策略，零 LLM 调用） |
| `message_count` | int | 消息总数（不含 system） |

### 加载规则

```python
def load_context(self, system_prompt: str) -> list[dict]:
    context = [{"role": "system", "content": system_prompt}]  # 第 0 项
    # 跳过第 1 行（meta），读取后续所有行
    for line in lines[1:]:
        context.append(json.loads(line))
    return context
```

## 会话 ID 生成

```python
def _generate_sid() -> str:
    base = datetime.now().strftime("s_%y%m%d_%H%M%S%f")  # 微秒级精度
    sid = base
    for i in range(100):
        if not os.path.exists(_session_path(sid)):
            return sid
        sid = f"{base}_{i}"  # 冲突时加自增后缀
    import random
    return f"{base}_{random.randint(1000, 9999)}"
```

**格式**：`s_YYMMDD_HHMMSSffffff`（微秒级，6 位微秒）

**冲突处理**：如果同一微秒内生成重复 ID，依次尝试 `_0`、`_1`……`_99` 后缀。极端情况下加随机后缀。

**文件名**：`s_260606_160000000000.jsonl`

**文件模式匹配**：

```python
SID_PATTERN = re.compile(r"^s_\d{6}_\d{12,}.*\.jsonl$")  # 微秒级 sid
```

## 会话终结：ExitReason

`portal.ctl.close(reason=...)` 以枚举 `ExitReason` 取代原散落的
`silent_shutdown` / `nuclear_exit` 布尔，终结语义收敛为一处：

| reason | 保存上下文 | 摘要 | 删除会话 | 前端提示 |
|--------|-----------|------|---------|---------|
| `FINAL` | ✅ | ✅ | ❌ | 显示退出提示 |
| `RECYCLE` | ✅ | ✅ | ❌ | 静默（reload / webui 重建） |
| `DISCARD` | ❌ | ❌ | ✅ | 静默（原 `nuclear_exit` / acp 退出） |

会话文件（`~/.local/share/fp/sessions/<sid>.jsonl`）的产出与销毁由此统一：
`FINAL` / `RECYCLE` 落盘并写摘要，`DISCARD` 删除当前会话文件后静默。

## 热重启续接：ReloadDirective

热重启（reload）后的续接消费收编为 `portal.ctl.take_reload()`，返回结构化结果：

```python
@dataclass(frozen=True)
class ReloadDirective:
    notice: str | None          # kind=command 的完成提示行（前端自行渲染），None = 无
    should_continue: bool       # kind=tool 的有效续接，True 时前端驱动续接
```

它取代原前端手写的 `consume_reload_handoff` + `_reload_notice` + `_pending_continue`
样板（置位与清空均在内部完成），前端只读结构化结果：

```python
d = portal.ctl.take_reload()
if d.notice:
    前端渲染(d.notice)
if d.should_continue:
    resp = await portal.run.continue_(io=...)
```
