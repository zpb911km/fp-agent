# 扩展分发（fp ext）操作指南

> 写给 **FP 自己** 的操作手册：怎么正确使用 `fp ext` 管理扩展资产。
> **源码真相**：`packages/fp/src/fp/ext.py`（命令实现）、`ext_assets.py`（路径模型）、`ext_store.py`（registry/audit）、`ext_scanner.py`（静态扫描）。文档可能滞后，行为一律以源码为准。
> 深度设计文档：`docs/dev/资产分发系统.md`。

---

## 0. 一句话心智（先记住这个）

> **分享 = 移动。** 资产任何时刻只有一份实体：
> `private/` 是工作区（分享即移出）、`public/` 是发布物（收回即移入）、`fetched/` 是安装缓存。
> promote/demote 都是**移动**不是复制，杜绝多重副本失同步。**勿回退成复制模型。**

---

## 1. 目录与元数据

| 路径 | 角色 | git | 说明 |
|---|---|---|---|
| `{DATA}/private/` | 私有工作区 | 有，**禁 remote** | 唯一事实源，自写资产放这 |
| `{DATA}/public/` | 发布仓库 | 有，可 push | 根含 `fp.ext.json` 库清单 |
| `{DATA}/fetched/` | 外来安装缓存 | 无 | 来自 fetch+install，只读 |
| `{DATA}/ext-registry.json` | fetched 纳管登记 | 不属于仓库 | `status`: pending_review → active |
| `{DATA}/ext-audit.jsonl` | 审计日志（追加式） | 不属于仓库 | 每行一条动作 |

**资产类型 → 子目录**（`ASSET_TYPES`）：

| 类型 | 子路径 | 文件形态 |
|---|---|---|
| `tools` | `tools/extensions/` | `*_plugin.py`，或目录 `<name>/` 内含 `*_plugin.py` |
| `commands` | `commands/` | `*.py`，或目录 `<name>/` 内含非 `_` 开头 `.py` |
| `plugins` | `plugins/` | `*_plugin.py` 或包（目录 `__init__.py`） |
| `memory` | `memory/` | `*.md`，或目录 `<name>/` 内含 `.md` |

**加载优先级**：`private > public > fetched`（同名后加载覆盖 + 警告）。

**资产形态**：单文件与目录型均支持（`info`/`share`/`init` 已对齐）；目录名 ≠ 语义名时靠 manifest `name` 兜底定位。

`{DATA}` = `get_data_dir()`：Linux `~/.local/share/fp/`。

## 2. 命令速查表

| 命令 | 做什么 | 关键点 |
|---|---|---|
| `new <type> <name>` | 生成脚手架到 `private/`（默认 version `0.1.0` / license **GPL-3.0** copyleft） | type ∈ tools/commands/plugins/memory |
| `init <dir>` | 补/校验 `__fp__` manifest（补的默认同上） | 给老资产补协议 |
| `list` | 三来源资产清单 | 一眼看全 |
| `info <name>` | 资产详情 | |
| `check` | 存量体检 | unmanaged + 静态扫描 + 审计核对 |
| `promote <name> [--force] [--push]` | 私有→公开（移动+登记+双仓 commit） | 前置见下 |
| `demote <name>` | 公开→私有（移动+移除登记+双仓 commit） | 只查 public；同名拒绝 |
| `share [--push] [--force]` | 校验 public 仓库 + commit + 可选 push | 强制：库清单/__fp__/孤儿 |
| `fetch <source>` | 拉取到暂存区 + 扫描 + 登记 pending | git URL / 单文件 URL / 本地路径 |
| `review <name> --approve\|--reject [--note]` | 记录审查结论 | **install 门禁** |
| `install <name> [--source] [--force]` | 暂存区 → `fetched/` | 须先 `--approve` |
| `remove <name>` | 删除（已装资产进 `.trash` 可恢复 + **自动 commit**） | 未安装待审直接清 staging |
| `update <name>` | 重新拉取覆盖 fetched 资产 | |
| `migrate` | 手动存量迁移 | 老结构存在时才需要 |

## 3. 三大工作流（实操顺序）

### A. 自写资产 → 发布（最常用）

```
1. fp ext new tools mytool            # → private/tools/extensions/mytool_plugin.py
2. 编辑实现（抄内置范例，见 扩展工具.md）
3. fp ext check                       # 可选：先体检一遍
4. fp ext promote mytool [--force]    # 移动进 public + 登记库清单 + 双仓 commit
5. fp ext share --push [--force]      # 校验 + commit + push 到远程
```
→ 他人 `fp ext fetch <仓库URL>` 即可安装。

### B. 安装外来资产

```
1. fp ext fetch <URL 或本地路径>
2. 【自举铁律】用 read_file 读暂存区源码做语义审查（工具调用，不是跳过！）
3. fp ext review <name> --approve --note "审查结论"
4. fp ext install <name> --source <URL>
5. 告知用户执行 /reload（或重启）→ 新会话生效
```

### C. 收回已发布资产

```
1. fp ext demote <name>     # public → private，移除清单登记，双仓 commit
2. fp ext share --push      # public 仓库同步（注意此时资产已在 private，public 已无此资产）
```

## 4. 踩坑地图（实测 2026-08-04 实战验证）

| # | 现象 | 原因 | 解法 |
|---|---|---|---|
| 1 | `promote` 报"public 仓库缺少库级清单" | public 根没有 `fp.ext.json` | 首次分享前先创建（schema/author/license/assets） |
| 2 | `promote`/`share` 静态扫描误报 `exec-import: import os` | 扫描器对 `import os/sys` 一律命中，实际只是 `os.walk` | 确认无 `os.system/popen/subprocess` 后 `--force` |
| 3 | 扫描误报 `privacy-user: zpb` | `__fp__` 块里 `"author"` 被当隐私 | `--force`（author 是有意公开声明） |
| 4 | `share --push` 只警告"无 remote，跳过 push" | public 仓库没配 remote | `git remote add origin <SSH URL>`；本机无 HTTPS token，用 SSH |
| 5 | install 后当前会话用不了 | 加载器会话启动时扫描，不热重载 | 请用户 `/reload`，不要尝试 IPC |
| 6 | 仓库里出现 `__pycache__/*.pyc` 被 commit | 加载目录在运行中生成 pyc，`commit_all` 全量 add | 两仓库都加 `.gitignore`（`__pycache__/ *.pyc .trash/`）+ `git rm -r --cached` |
| 7 | `demote` 报"private/ 已存在同名资产" | 防止覆盖工作区文件 | 先处理 private 同名资产再重试 |
| 8 | `git push` 失败（若日后用 HTTPS） | 无 credential | 本机已验证 SSH 认证 OK，统一走 `git@github.com:...` |
| 9 | `install` 名称与 fetch 资产名不一致 | staging 命名：git URL→`fetch_git`、单文件→文件名、本地→目录名 | install 有兜底查找；拿不准先 `fp ext list` 看 |

## 5. 检查与验证

```bash
fp ext list                  # 资产总览（三来源）
fp ext check                 # 体检（unmanaged/扫描/审计）
git -C {DATA}/private status --short   # 私有仓库干净？
git -C {DATA}/public status -sb        # 公开仓库干净？是否落后远端？
git ls-remote origin         # 远端 HEAD 是否 = 本地 HEAD（验证 push 成功）
```

## 6. 边界与约定

- **你能跑 `fp ext`**（它是 CLI 子进程，你通过 bash 调用），但**不能触发 `/reload`**——装完/写完扩展后必须请用户执行。
- `--force` 只跳静态扫描，**库清单 / __fp__ 自描述 / 孤儿文件校验仍强制**。
- `promote` 前置：资产在 `private/` 且 public 已有 `fp.ext.json`；目标已存在则先删旧版再移入（保证单版本）。
- `demote` 只查 public（不能走 `_find_asset`，它默认优先 private）。
- private 仓库有 `ensure_no_remote` 守卫，别给 private 加 remote。
- 审计两段式：`fetch` 登记 pending → `review` 记录结论 → `install` 落地，全程可回溯。
